# 業務概要（Local Sights）

## 何のためのものか

Local Sights は、Amazon CloudWatch Logs のログを手元の Mac で読むためのデスクトップアプリである。AWS マネジメントコンソールを開かずに、選んだロググループの指定した時間範囲のログを、すべてのストリームから集めて時刻順に一覧できる。開発者 1 人のチームが、会社の PC（macOS、Apple Silicon）に入れて使う前提で作っている。

- 利用者：自社の AWS アカウントのログを調べる開発者や運用担当者。自分の AWS 認証情報（プロファイル、SSO を含む）で読む。
- 呼ぶ AWS の操作は読み取りの 3 つだけ：`DescribeLogGroups`、`DescribeLogStreams`、`GetLogEvents`。必要な IAM 権限もこの 3 つ（`README.md`）。
- 外部への送信はしない：テレメトリやクラッシュレポートは送らない。ログはメモリに置き、設定でオンにしたときだけディスクキャッシュに書く。

## 業務上の決まり（コードで守られているもの）

- 読み取りの 3 操作以外は呼ばない：AWS への唯一の境界 `CloudWatchLogsGateway` に他の操作が無い（[api-documentation.md](api-documentation.md)）。
- 秘密の認証情報（シークレットアクセスキー、セッショントークン、SSO トークン）とアクセスキー ID を画面・ログ・キャッシュに出さない：失敗の詳細は許可リストの項目だけから作り、さらに伏せ字にかける（`failure.rs`）。
- 自動テストと CI は AWS に接続しない：AWS 呼び出しは trait の裏にあり、テストは偽物に差し替える。
- 取得の途中でエラーが起きても、取れたページは残して表示する（U1 の決定 Q3）。
- 件数の上限は設けず全件を取得・表示する（U1 の決定 Q4）。
- 前回の選択は覚えない（U2 の決定）。起動時は「何も選ばない」としていた U2 の決定を後の修正（gate fix 14c）が置き換え、今は SDK の既定プロファイルを選んだ状態で始まる。その既定のリージョンがあれば、ロググループの一覧も起動時に読む（`session.rs` の `with_catalog_and_time_zones`、`startup_listing`）。

## 今回の intent（261012-parallel-fetch）との関わり

今回の作業は、ストリームの多いロググループで待ち時間が延びる問題を、複数のストリームを同時に読むことで縮めるものである。東京リージョンの `GetLogEvents` の上限はアカウント全体で 1 秒あたり 25 回で引き上げできず、その半分程度（1 秒あたり 12 回前後）に抑えると決めている（ideation の制約 C-T2、C-O1）。あわせて、並行時の「3 ストリーム続けて使い切ったら残りを失敗」の作り直し、状態行への経過時間の追加、利用者による取り消し（［取得］が［取り消し］に変わり、取れたログは残り、終わらなかったストリーム数を警告で示す）を行う。ディスクキャッシュの見かけの振る舞いは変えない。現状のコードでの関わり方は [architecture.md](architecture.md) の「改善の余地」と [code-quality-assessment.md](code-quality-assessment.md) の「今回の intent への影響」にまとめた。
