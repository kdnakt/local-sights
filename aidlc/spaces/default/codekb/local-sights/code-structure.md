# Code Structure

> リポジトリ `local-sights` のパッケージ／モジュール構成とファイル分類。2026-10-12 の全体スキャン（コミット `9d08cbf`）に基づく。部品ごとの責務は `component-inventory.md`、依存は `dependencies.md` を参照。

## Repository Layout

```

├── package.json / package-lock.json   # npm（画面、Tauri CLI、スクリプト）、版 0.1.0

├── docs/
│   ├── install.md             # 配布された .dmg のインストール、初回起動の警告、更新、戻し方

├── scripts/

│   ├── release/versions.test.ts    # Vitest
│   └── render-icon.mjs             # icon.svg → icon.png（透過検証付き）
├── crates/local-sights-core/  # GUI 非依存ライブラリ
│   ├── Cargo.toml
│   ├── src/ ...               # 下記

│   └── examples/fetch_check.rs # 開発者専用の実 AWS 確認
├── src-tauri/                 # Tauri アプリ
│   ├── Cargo.toml, build.rs, tauri.conf.json
│   ├── capabilities/default.json
│   ├── permissions/autogenerated/*.toml   # コマンドごとの権限（tauri-build 生成、コミット済み）
```

## Code Patterns

- **判断と流れの分離**: 純粋関数のモジュール（`*/mod.rs`、`cache/plan.rs`、`sso_login.rs`、`scripts/release/versions.ts`）と I/O を伴うモジュール（`*/listing.rs`、`*/planner.rs`、`cache/mod.rs`、`sso_cli.rs`、`check-version.mjs`）を分け、純粋側を先にテストする。
- **シンク／ストア trait による逆依存**: `FetchSink`、`ListingSink`、`TimelineStore`、`TimeZoneContext`、`CloudWatchLogsGateway`。core は呼び手（Tauri、例、テスト）を知らない。
- **`Result` によるエラー伝播**: テスト外に `unwrap()` / `expect()` は 0 件。Mutex の毒化は `PoisonError::into_inner` で回復。
- **世代番号による競合排除**: `connectionGeneration`、`timelineVersion`、`filterResultVersion`、`discardGeneration`、`attemptId` を往復させ、古い要求や遅れた応答を捨てる。
- **コマンドの 4 重登録**: 1 つのコマンドは `build.rs`、`capabilities/default.json`、`lib.rs` の `generate_handler!`、`src/api.ts` に現れる（`src/commandRegistration.test.ts` が整合を検査）。
- **文書の規約**: Rust は `#![warn(missing_docs)]`、各モジュール先頭に作業単位と BR/FR 番号を引いた説明。TS も JSDoc で同じ番号を引く。
- **命名**: Rust は snake_case / UpperCamelCase / SCREAMING_SNAKE_CASE、TS は camelCase、部品は PascalCase（team.md Code Style）。
