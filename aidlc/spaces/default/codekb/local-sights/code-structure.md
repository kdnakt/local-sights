## コードの型（パターン）

- **純粋な判断と流れの分離**：判断は副作用の無い関数（例：`paging::decide`、`streams::is_selected`、`RetryPolicy::decide`、`decide_job_status`、`cache::plan::decide_write`、`cache_notices`）で、テストはそれぞれのモジュールの中にある。流れの関数（`run_fetch`、`plan_streams`、`fetch_stream`、`run_listing`）は trait を通してだけ外に触れる。
- **受け口の trait（観測者）**：`FetchSink`、`ListingSink` で進み具合を呼び出し側に渡す。中核は呼び出し側を知らない（ADR-007）。`DeferredFinishSink` は包んで `on_finished` だけを保留する装飾。
- **画面状態の一元化**：`AppSession` が状態を持ち、`view()` がスナップショット `SessionView` を作る。画面からの操作は `Result<_, SessionError>` で断られることがあり、断りの理由は文言キーで返る。
- **版と世代**：`timeline_version`（追加・破棄のたびに上がる）、`discard_generation`、`connection_generation`、`filter_result_version`、`job_id`、`fetch_number` で、遅れて届いた結果や古い操作を捨てる。
- **ロックは短く**：`Mutex<LogView>` はページ 1 つ分、絞り込みの 1 塊分、キャッシュへの写し 4,096 件分だけ取る。ロックの順はセッション → LogView。毒されたロックは中身を取り戻して続ける（`unwrap_or_else(PoisonError::into_inner)`）。
- **重い作業は別スレッド**：キャッシュの読み書き、設定ファイル、絞り込みの走査、AWS CLI は `spawn_blocking` かスレッドで動かす。
- **エラーは `Result` で返す**：テスト以外に `unwrap()`／`expect()` は無い（team.md の決まり）。診断は標準エラーにだけ、安全な詳細だけを書く。
- **画面は表示だけ**：時刻の書式、絞り込み、検証はすべて中核で行い、画面は中核が作った文字列とキーを表示する。
