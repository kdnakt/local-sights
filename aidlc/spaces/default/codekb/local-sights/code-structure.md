`export_boundary.rs`（新、240 行）は `dialog_filter`、`ask_save_path`（`blocking_save_file`）、`copy_to_clipboard`、`failure_kind`（`io::ErrorKind` → `ExportFailure`）、`write_file_atomically`（一時ファイル → rename）を持ち、OS のエラーの言葉は標準エラーにだけ出す。`cfg` は使わない。`sso_cli/mod.rs` は決め事（候補パス、5 分の時間切れ、2 秒の猶予、行の読み）を持ち、`unix.rs` / `windows.rs` が OS の 3 関数を提供する。`browser.rs` は `cfg` で 2 つの `open_url`。

## 画面（`src/`）

`main.tsx` が `App` を描く（`applyDesignTokens` を当てるだけで、言語は決めない）。`App.tsx` が 1 つの窓を組み立て、`session.language` と OS の言語から `resolveLocale` で 1 つの `locale` を決め、`createTranslator`、Cloudscape の `I18nProvider`（`all.en` / `all.ja`）、`document.documentElement.lang` をそれに従わせる（`App.tsx:204-213`）。`api.ts` が Tauri の型と `invoke` の関数（34 コマンド）、イベントの購読、部分更新の合成（`mergeSessionView`、`withProgress`、`withFilter`）を持つ。`components/` は 1 部品 1 ファイルで、同名の `.test.tsx` が隣にある。`hooks/` は開いた行の状態（`expansionState.ts`）、ペインの幅（`localStorage`）、色の様式、デバウンス、Escape、初回フォーカス、行の配置と窓。`i18n/messages.ts` は `messages` の表（`en` / `ja`）、`englishSingular`（本数が 1 のときの英語の単数形）、`detectLocale`、`resolveLocale`、`translate`（`{name}` の置き換えと単数形の選択）、`createTranslator`。`i18n/regions.ts` は `REGION_NAMES`（日英）、`regionLabel`、`filterRegionOptions`。`jsonPretty.ts` は `findJson`（最初の完全な JSON オブジェクト／配列を字句走査で探す。`MAX_DEPTH = 256`、`MAX_CANDIDATES = 64`、`MAX_MESSAGE_LENGTH = 1 MiB`）と `prettyPrint`。`analytics.ts` はクエリの画面の純粋な補助（`problemText`、`problemRange`、`QUERY_HIGHLIGHT_RULES`（Ace の色分け。命令は `fields|filter|sort|limit`、関数は `toMillis` だけ）、`completionItems`、`QUERY_EXAMPLES`（5 つ）、`firstLine`、`limitSelection`）。

## コードの決まりごと（読み取れたもの）

- **文書化**：中核は `#![warn(missing_docs)]`。モジュールの先頭と公開項目に説明があり、要件の ID（`U2:BR4.6`、`NFR2`、`review R-01`）と作業の名前（`261022-small-features U2`）を引く。画面の部品も先頭に役割を書く。新しいモジュール（`export/`、`export_boundary.rs`、`jsonPretty.ts`、`regions.ts`）も同じ書き方。
- **エラー**：本番コードは `Result` で返す。`Mutex` は `unwrap_or_else(PoisonError::into_inner)`。`unwrap()` / `expect()` はテストと `tests/support/` に限る。OS のエラーの言葉は画面に出さず、種類（`ExportFailure`）に写す。
- **鍵の中と外**：書き出しは「鍵の中では可否の判定・仕事の開始・行の複製だけ、文字にする作業と OS の呼び出しは鍵の外の blocking スレッド」と決めてある（`export/mod.rs:11-17`）。クエリの評価も同じ型（鍵は 1 塊ずつ）。
- **OS 依存**：`cfg(unix)` / `cfg(windows)` は `sso_cli/`、`browser.rs`、`cache/mod.rs` のパーミッション、`main.rs` の `windows_subsystem` に限る。書き出しの OS の違いはプラグインに任せ、`cfg` を増やしていない。
- **秘密の扱い**：`failure.rs` がアクセスキーらしい文字を `[REDACTED]` にし、`sso_cli` は URL とコード以外の出力を捨てる。`settings.json` にプロファイル・リージョン・ロググループ・認証情報は書かない。
- **名前**：Rust は snake_case / UpperCamelCase / SCREAMING_SNAKE_CASE、TypeScript は camelCase、JSON は `camelCase`（`serde(rename_all)`。`ExportScreen` は camelCase、`ExportFormat` / `ExportTarget` は lowercase、`ExportNotice` は `kind` でタグ付け）。テスト名は英語の文。
- **登録の一致**：コマンドは 3 か所で同じ集合（Rust と TS の両方のテストで守る。数は固定しない）。
- **整形**：rustfmt、Prettier（printWidth 100、trailingComma all）、LF 固定。
