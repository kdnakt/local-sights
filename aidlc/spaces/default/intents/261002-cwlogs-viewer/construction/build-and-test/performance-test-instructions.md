# Performance Test Instructions — 性能の確認の手順

対象の目標は `inception/requirements-analysis/requirements.md` の NFR1〜NFR3。計測機はどれも「開発者の Mac」で、目視またはストップウォッチで測るものを含む。この環境（Linux のコンテナ）で測れるのは `#[ignore]` の速さのテストだけで、その値は参考値とする（質問票 Q2）。

## 目標

| ID | 目標 | 期待値 | 測り方 |
|----|------|--------|--------|
| NFR1 | 絞り込みが速い | 取得済み 10 万件に対して、入力から結果表示まで 10 秒以内 | 開発者の Mac で計測 |
| NFR2 | 大量件数でも操作できる | 取得済み 100 万件で、絞り込みの結果が 100 秒以内、ログ一覧のスクロールに 1 秒以内に反応、アプリが落ちない、100 万件を超えても取得を止めない | 開発者の Mac で、操作から画面が変わるまでを目視またはストップウォッチ |
| NFR3 | 取得中も画面が固まらない | 取得中にウィンドウの移動・リサイズ・スクロール・行の展開に 1 秒以内に反応し、取得中であることが表示される | 同上 |

## 自動の速さのテスト（リリースビルド）

ライブラリ側に、純粋なロジックの速さを測るテストが 5 件ある（`#[ignore]`、`--release` で実行）。

| テスト | 場所 | 測るもの | 関係する目標 |
|--------|------|----------|--------------|
| 10 万件の絞り込み | `log_view.rs` | FilterEngine の走査 | NFR1 |
| 100 万件の絞り込み | `log_view.rs` | 同上 | NFR2 |
| 100 万件・絞り込みあり・1 万件のページの切り出し | `log_view.rs` | LogView の行の読み出し | NFR2（スクロールの応答） |
| 100 万件の時刻順マージ 2 件 | `timeline.rs` | EventTimeline の追加と並べ替え | NFR2（取得を止めない） |

```bash
CARGO_INCREMENTAL=0 cargo test -p local-sights-core --release --lib -- timeline:: filter:: log_view:: --ignored
# 実行後、ディスクを空ける
rm -rf target/release
```

結果は `println!` で標準出力に出る（`filter of 100,000 events: ...` など）。`cargo test` は成功したテストの出力を隠すので、値を見るときは `-- --nocapture` を足す。

## 手元（macOS）での計測

GUI を通した値が目標の本体なので、以下は `npm run tauri dev` または `cargo build -p local-sights` で作ったアプリで行う。

1. **10 万件の絞り込み（NFR1）**：10 万件以上のイベントがある時間範囲を取得し、取得が終わったあとに絞り込みの文字列を入れる。入力を止めてから「絞り込み後 / 全件」の件数が変わるまでをストップウォッチで測る。10 秒以内なら達成。
2. **100 万件の絞り込みとスクロール（NFR2）**：100 万件以上の時間範囲を取得する（実際のロググループで足りなければ、取得中の件数がそれを超えるまで広い範囲を使う）。絞り込みの表示までが 100 秒以内、一覧のスクロール・行の展開の反応が 1 秒以内、アプリが落ちないこと、100 万件を超えても取得が続くことを確かめる。
3. **取得中の応答（NFR3）**：広い時間範囲の取得を始め、取得中にウィンドウの移動・リサイズ・一覧のスクロール・行の展開を行い、どれも 1 秒以内に反応すること、ステータス行に取得中が出ていることを確かめる。

## 結果の記録

- この環境で測った参考値と、手元の Mac の値はどちらも `test-results.md` の「性能」に書く。達成の判定（`Met`）は手元の Mac の値だけで行う。
- 手元で測るまで、NFR1〜NFR3 の判定は `Unverified`。

## 退行の検知

- 速さのテストは `#[ignore]` のため CI では走らない。純粋なロジック（FilterEngine・LogView・EventTimeline）を変える PR では、上の release コマンドを手元で実行して前回の値と比べる。
- 目安：100 万件の絞り込みがこの環境の参考値の 2 倍を超えたら、原因を見てから PR を進める。
