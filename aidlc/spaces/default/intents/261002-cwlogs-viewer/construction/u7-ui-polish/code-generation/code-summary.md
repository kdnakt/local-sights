## 主な判断

- **R-11（discardGeneration の持ち主）**：LogView が持ち、`clear()` の中で増やす。保持ログが空のときの `clear()` では増やさない（「実際に保持ログを空にしたときだけ」）。SessionView へは `sync_filter`（filter の要約を写す所）と接続の変更の所で写す。画面は SessionView と `row_positions` の答えのうち新しい方を正にする。
- **R-12（縮小）**：`rowLayout.ts` は U3 と同じ正規化（最大の仮想の上端 ↔ 最大のスクロール位置）。`visibleRange`・`anchorAt`・`scrollTopForAnchor`・`scrollTopToReveal` は画面の高さを入力に取る。U3 の `virtualScroll.test.ts` は期待値を変えずに通り、100 万件で End が末尾の行に届くテストを足した。
- **R-13（tabIndex と見出し）**：role=grid・tabIndex=0・aria-activedescendant は一覧の外枠に付け、見出しの行（aria-rowindex=1）をその中に置いた。展開部分の tabIndex=0 は「選んでいる行の、スクロールする展開部分」だけで、ほかは -1。
- **R-14 (2)（全角 2 倍）**：`isWideCodePoint` で East Asian Width が W・F のおもな範囲（CJK、ひらがな・カタカナ、ハングル、全角記号、絵文字のおもな範囲）を 2 文字ぶんに数える。範囲は近似で、測った値が来れば測った値を使う。
- **高さ**：展開部分の文字の要素（box-sizing: border-box、上下 6 px の余白）の高さを ResizeObserver の `borderBoxSize` で測る。測った値は一覧の幅と組で持ち、幅が変わったら見積もりに戻す。見積もりには、展開したときにメッセージの各行の幅（列数）だけを覚え、本文そのものは持たない。
- **位置の問い合わせ**：`useRowPositions` は呼び出しを同時に 1 つにし、途中で来た求めは答えが返ってから、その時点のキーで 1 回だけ送る。答えの版が手元より古ければ捨てる。アンカーは、画面が見ている版より古い答えでは使い切らず、次の答えで合わせる（版が続けて変わる場合）。アンカーの行が消えたら同じ位置の行を上端にする（BR1.8）。
- **選択**：選んでいる行は「キーと位置」。キーは行が届いていればその場で、届いていなければ位置だけを持ち、問い合わせのときに読み込み済みの行から引く。Enter・Space は行が届いていなければ何もしない。
- **エラー**：場面は表示の場所で決める（取得全体＝Fetch、左ペイン＝Listing、失敗の一覧＝Stream。失敗の一覧の「ストリームの列挙」の失敗も取得の一部なので Stream）。詳細は空白だけなら添えない。
- **終了の確認**：取得中（phase が Fetching。書き込み中もこのうち）に加え、取得のタスクが異常終了したあとに書き込みが残っているときも止める（`WriteTracker`）。確認中は新しい取得を受け付けない（`ConfirmationPending`）。[Close] は印を立ててから中断と `app.exit(0)` を行い、そのあとの ExitRequested・CloseRequested は止めない。
- **設定のファイル操作（U6 R-01）**：書き込み → （無効にしたときだけ）全削除、の順は `SettingsWork::run` の中で保つ。作業中は設定の別の操作と取得の開始を `Busy` で断る。作業中にダイアログを閉じた場合、結果（設定の値）は反映し、知らせは出さない。
- **色**：`confirm-backdrop` の `rgb(0 0 0 / 30%)` を `color-mix(in srgb, CanvasText 30%, transparent)` に変え、決め打ちの色をなくした。

## R-14 (1) 意図した契約の変更の記録

`inception/domain-design/components.md` は展開している行を **SessionState.expandedRows**（ライブラリの状態）としていたが、U7 では **画面の中（`src/hooks/expansionState.ts` と `LogTable`）だけで持ち、ライブラリには渡さない**。ライブラリが持つのは位置の問い合わせ（`LogView::positions_of`）と破棄の世代（`discard_generation`）だけ。理由は functional-spec.md §5・§8 のとおり（表示だけの状態で、行の高さの測り方と一緒に扱う必要がある）。承認済みの上流の文書は書き換えていない。

**Build and Test の確認項目に入れること**：components.md の SessionState.expandedRows と実装の違いが上の意図した変更であること（AppSession・SessionView に展開の状態がないこと、画面を読み込み直すと展開が閉じること）を確かめる。

## 計画との違い

1. `run_fetch_with_cache` の保持ログの引数を `&T` から `&Arc<T>`（`T: 'static`）に変えた。写し取りを `spawn_blocking` に移すため（U6 R-04）。呼び出し元（`src-tauri`、`coordinator.rs` と `tests/u6_cache_flow.rs` のテストの補助関数）を合わせた。テストの期待は変えていない。
2. Hit の途中の中断の `cache_outcome` を `NotUsed` から `NotSaved` に変えた（U6 R-06 が求める結果に合わせた）。
3. `virtualScroll.ts` は消さず、`rowLayout.ts` の上の固定行高の窓口として残した。U3 の `virtualScroll.test.ts` を期待値を変えずに新しい計算で通すため。一覧そのものは `rowLayout.ts` を直接使う。
4. Tauri の `find_row_position` コマンドと `api.findRowPosition` は残した（画面はもう使わない）。計画は新しいコマンドの権限を足すことだけを書いており、消すかは決めていないため。
5. 終了の確認中（Pending）は `begin_fetch` を `ConfirmationPending` で、設定のファイル操作中は `Busy` で断るようにした（計画に明記はない。ダイアログが開いている間の取得の開始と、全削除と書き込みのぶつかりを防ぐため）。
6. 既存の LogTable のテスト 11 件は、U3 のスクロールのキー（BR1.5 で選択に置き換え）と `findRowPosition`（`rowPositions` に置き換え）を前提にしていたため書き直した。U3〜U5 の観点（窓の行だけを描く、時刻の文字、TZ の切替で引き直す、追加で上端を保つ、古い答えを捨てる、新しいフィルタで一番上）は残した。
7. `logGroups.partial` の文言から `{kind}` を除いた（「一覧は途中までです。」。理由は BR2.2 の文で続けて出す）。`status.failed`・`table.scroll` を除き、`table.expanded` を足した。`failure.kind.*` はコアが種類の名前に使うキーとして残した。
8. 終了の確認ダイアログの役割は `alertdialog` にした（失われるものを知らせる確認のため）。

## まだ確かめていないこと・未解決

- **BR2.2 の日本語の文言のボタン名**：正本どおり、日本語の次の行動に「[Fetch] でもう一度取得してください」と書いたが、日本語の画面のボタンは「取得」である。BR2.2 の「ボタン名は画面の表示どおり」と食い違う。英語の「…, then Press [Fetch] to fetch again.」も文中で大文字の Press になる。どちらも正本の文言を変えずに実装し、README の確認項目に入れた。直すなら機能設計の文言の判断が要る。
- Tauri の閉じる・終えるの実際の動き（特に macOS の Cmd+Q と Dock の終了で `RunEvent::ExitRequested` が来るか）、ダークモードの切替、1024×640 での見た目、100 万件で展開とスクロールの体感、WebKit の ResizeObserver の `borderBoxSize` は、自動テストでは確かめていない。README の U7 の項目で開発者本人が手元で確かめる。
- jsdom には ResizeObserver も実際の配置もないため、高さの測定は小さな偽物で値を渡して確かめた。実際の `scrollHeight > clientHeight` による「中でスクロールするか」の判定は手元の確認に回す。
- 全角の判定（R-14 (2)）は East Asian Width のおもな範囲の近似。見積もりがずれても、画面に出た展開部分は測った値に置き換わる。
- 書き込み中に [Close] したときに残る一時ファイルは、U6:BR3.4 のとおり次の書き込みか全削除で消える。自動テストでは確かめていない（README の確認項目）。
