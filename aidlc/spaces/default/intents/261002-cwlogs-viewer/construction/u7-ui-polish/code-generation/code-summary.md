## 主な判断

- **R-11（discardGeneration の持ち主）**：LogView が持ち、`clear()` の中で増やす。保持ログが空のときの `clear()` では増やさない（「実際に保持ログを空にしたときだけ」）。SessionView へは `sync_filter`（filter の要約を写す所）と接続の変更の所で写す。画面は SessionView と `row_positions` の答えのうち新しい方を正にする。
- **R-12（縮小）**：`rowLayout.ts` は U3 と同じ正規化（最大の仮想の上端 ↔ 最大のスクロール位置）。`visibleRange`・`anchorAt`・`scrollTopForAnchor`・`scrollTopToReveal` は画面の高さを入力に取る。U3 の `virtualScroll.test.ts` は期待値を変えずに通り、100 万件で End が末尾の行に届くテストを足した。（レビュー R-05 で、使われなくなった `scrollTopForKey` のテスト 1 件を外し、`preservedScrollTop` は同じ計算の `scrollTopForRow` に替えた。残った期待値は変えていない）
- **R-13（tabIndex と見出し）**：role=grid・tabIndex=0・aria-activedescendant は一覧の外枠に付け、見出しの行（aria-rowindex=1）をその中に置いた。展開部分の tabIndex=0 は「選んでいる行の、スクロールする展開部分」だけで、ほかは -1。
- **R-14 (2)（全角 2 倍）**：`isWideCodePoint` で East Asian Width が W・F のおもな範囲（CJK、ひらがな・カタカナ、ハングル、全角記号、絵文字のおもな範囲）を 2 文字ぶんに数える。範囲は近似で、測った値が来れば測った値を使う。
- **高さ**：展開部分の文字の要素（box-sizing: border-box、上下 6 px の余白）の高さを ResizeObserver の `borderBoxSize` で測る。測った値は一覧の幅と組で持ち、幅が変わったら見積もりに戻す。見積もりには、展開したときにメッセージの各行の幅（列数）だけを覚え、本文そのものは持たない。
- **位置の問い合わせ**：`useRowPositions` は呼び出しを同時に 1 つにし、途中で来た求めは答えが返ってから、その時点のキーで 1 回だけ送る。答えの版が手元より古ければ捨てる。アンカーは、画面が見ている版より古い答えでは使い切らず、次の答えで合わせる（版が続けて変わる場合）。アンカーの行が消えたら同じ位置の行を上端にする（BR1.8）。
- **選択**：選んでいる行は「キーと位置」。キーは行が届いていればその場で、届いていなければ位置だけを持ち、問い合わせのときに読み込み済みの行から引く。Enter・Space は行が届いていなければ何もしない（`LogTable` のキー処理。純粋な関数 `toggleSelected` はレビュー R-05 で未使用として削除した）。
- **エラー**：場面は表示の場所で決める（取得全体＝Fetch、左ペイン＝Listing、失敗の一覧＝Stream。失敗の一覧の「ストリームの列挙」の失敗も取得の一部なので Stream）。詳細は空白だけなら添えない。
- **終了の確認**：取得中（phase が Fetching。書き込み中もこのうち）に加え、取得のタスクが異常終了したあとに書き込みが残っているときも止める（`WriteTracker`）。確認中は新しい取得を受け付けない（`ConfirmationPending`）。[Close] は印を立ててから中断と `app.exit(0)` を行い、そのあとの ExitRequested・CloseRequested は止めない。経路はウィンドウの閉じる（`CloseRequested`）、アプリメニューの Quit と Cmd+Q（`on_menu_event`、レビュー R-01）、`app.exit` と最後のウィンドウ（`ExitRequested`）。Dock の終了は止められない（下の既知の制約）。
- **設定のファイル操作（U6 R-01）**：書き込み → （無効にしたときだけ）全削除、の順は `SettingsWork::run` の中で保つ。作業中は設定の別の操作と取得の開始を `Busy` で断る。作業中にダイアログを閉じた場合、結果（設定の値）は反映し、知らせは出さない。
- **色**：`confirm-backdrop` の `rgb(0 0 0 / 30%)` を `color-mix(in srgb, CanvasText 30%, transparent)` に変え、決め打ちの色をなくした。

## 計画との違い／既知の制約

1. `run_fetch_with_cache` の保持ログの引数を `&T` から `&Arc<T>`（`T: 'static`）に変えた。写し取りを `spawn_blocking` に移すため（U6 R-04）。呼び出し元（`src-tauri`、`coordinator.rs` と `tests/u6_cache_flow.rs` のテストの補助関数）を合わせた。テストの期待は変えていない。
2. Hit の途中の中断の `cache_outcome` を `NotUsed` から `NotSaved` に変えた（U6 R-06 が求める結果に合わせた）。
3. `virtualScroll.ts` は消さず、`rowLayout.ts` の上の固定行高の窓口として残した。U3 の `virtualScroll.test.ts` を期待値を変えずに新しい計算で通すため。一覧そのものは `rowLayout.ts` を直接使う。
4. Tauri の `find_row_position` コマンドと `api.findRowPosition` は、最初は残したが、レビュー R-05 で削除した（`build.rs`・`capabilities/default.json` の権限と `permissions/autogenerated/find_row_position.toml` も削除）。
5. 終了の確認中（Pending）は `begin_fetch` を `ConfirmationPending` で、設定のファイル操作中は `Busy` で断るようにした（計画に明記はない。ダイアログが開いている間の取得の開始と、全削除と書き込みのぶつかりを防ぐため）。
6. 既存の LogTable のテスト 11 件は、U3 のスクロールのキー（BR1.5 で選択に置き換え）と `findRowPosition`（`rowPositions` に置き換え）を前提にしていたため書き直した。U3〜U5 の観点（窓の行だけを描く、時刻の文字、TZ の切替で引き直す、追加で上端を保つ、古い答えを捨てる、新しいフィルタで一番上）は残した。
7. `logGroups.partial` の文言から `{kind}` を除いた（「一覧は途中までです。」。理由は BR2.2 の文で続けて出す）。`status.failed`・`table.scroll` を除き、`table.expanded` を足した。`failure.kind.*` はコアが種類の名前に使うキーとして残した。
8. 終了の確認ダイアログの役割は `alertdialog` にした（失われるものを知らせる確認のため）。
9. **BR2.2 の {retry} の文言を正本から変えた（人間が承認済み、レビュー R-02）**。日本語は `error.retry.fetch` を「[取得] でもう一度取得してください」にした（画面のボタンは「取得」。`error.retry.listing` の「[再読み込み]」は画面のボタン「再読み込み」と一致していたので変えていない）。英語は文の中に入るため小文字の「press」で始め（「press [Fetch] to fetch again」「press [Reload] to load the list again」）、例えば「Wait a while, then press [Fetch] to fetch again.」となる。{retry} が文頭に来る Other だけは、`errorLines` が頭文字を大文字にして「Press [Fetch] to fetch again. If it keeps happening, check the details.」とする。`functional-spec.md` は書き換えていない（正本との違いはこの記録で示す）。
10. **既知の制約：Dock の終了は確認できない（レビュー R-01、BR3.1 (2) は一部だけ満たす）**。今の tao 0.37.1／muda 0.20.0 では、Dock のメニューの「終了」は `applicationWillTerminate` から直接プロセスの終わりに進み、`RunEvent::ExitRequested` もメニューのイベントも来ないため、アプリから止められない。取得中に Dock から終えると、確認なしで終わる（取得途中のログは失われ、キャッシュには書かない）。Cmd+Q とアプリメニューの Quit は、このアプリの項目にして止められるようにした。直すには `applicationShouldTerminate:` を返す仕組み（delegate の追加など）が要り、MVP では行わない。README の U7 の確認項目に「Dock の終了は確認できない（既知の制約）」を入れた。
11. **アプリメニューを独自に置いた（レビュー R-01）**。macOS では Tauri の既定のメニューの代わりに `app_menu` を使う。中身は既定とほぼ同じ（アプリ名のメニュー：About・Services・Hide・Hide Others・Show All・Quit、Edit：Undo・Redo・Cut・Copy・Paste・Select All、View：Full Screen、Window：Minimize・Maximize・Close Window）で、Quit だけをこのアプリの項目（`CmdOrCtrl+Q`）にした。既定にあった空の Help と、Window と重なる File の Close Window は置いていない。Edit の標準の項目を残したので、Cmd+C・Cmd+V などはこれまでどおり効く。macOS 以外ではメニューを置かない（これまでと同じ）。
12. **開ける行の上限と問い合わせの上限（レビュー R-04）**。画面で同時に開ける行を 10,000 までにし、それ以上は開かずに一覧の下に「同時に開ける行は 10,000 行までです。…」を出す（`role="status"`）。`row_positions` が受け付けるキーは、開いている行 10,000 に選んでいる行と先頭の行を足した 10,002 まで（`MAX_POSITION_KEYS`）とし、超えたら黙って切り詰めずに `rows.tooManyKeys` の Err を返す（画面はエラー欄に出す）。指示の「上限 10,000」は開ける行の数とし、問い合わせの上限はその分の 2 を足した値にした（開ける行を 10,000 にしたまま問い合わせを 10,000 で切ると、上限いっぱいのときに必ずエラーになるため）。
13. **書き込み中の印の再送（レビュー R-03）**。`WriteTracker` に `on_idle` を足し、最後の書き込みが終わったときに呼ぶ。アプリはそこで（非同期の実行環境に渡してから）取得中でなければ `session-changed` を送る。取得中の書き込みの終わりでは送らない（取得の終わりで送るため）。
