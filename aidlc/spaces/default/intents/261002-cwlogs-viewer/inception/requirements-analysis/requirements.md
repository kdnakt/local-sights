## 1. 意図の分析

- **何を達成したいか**：マネジメントコンソール（FilterLogEvents / Logs Insights）では見えない古いロググループの過去ログを、確実に閲覧できるようにする（intent-statement、D-01）。CLI の get-log-events では同じログが見えたため、GetLogEvents を使う（D-04、C-T1）。
- **誰のためか**：開発者本人。あわせて OSS として公開する（D-02）。
- **いつまでに**：MVP の完成目標日は 2026-10-10（D-23）。
- **種類と規模**：新規開発（グリーンフィールド）。macOS 向けの Rust 製デスクトップ GUI アプリ 1 つ（IB-00、D-15、D-16）。AWS 側には何も作らない（C-T8）。
- **複雑さ**：Standard。機能は少ないが、API の制約（ページング・スロットリング・ストリーム単位）と大量件数の扱いに注意が要る。

## 2. 機能要件

### FR1. AWS 接続の切り替え（IB-01）

- **FR1.1** アプリは、AWS CLI と同じ設定ファイル（`~/.aws/config`、`~/.aws/credentials`）に定義されたプロファイルの一覧を上部バーに表示し、1 つを選べるようにする（C-E1、C-E2）。
- **FR1.2** アプリは、SSO・アクセスキー・AssumeRole・環境変数のいずれの認証方式で定義されたプロファイルでも接続できる（C-E2、D-06）。
- **FR1.3** アプリは、リージョンを上部バーで選べるようにする。選択肢は AWS SDK が持つ公開リージョンの一覧とし、プロファイルに既定のリージョンがあれば、それを初期値にする（C-E1、レビュー R-06）。
- **FR1.4** プロファイルまたはリージョンを変えると、ロググループ一覧を取り直す（WF 画面 1）。
- **FR1.5** 認証に失敗したとき（SSO のログイン切れなど）は、何が起きたかと次の行動（例：`aws sso login` を実行する）を文字で表示する（WF 画面 5）。

受け入れ基準：
- Given SSO で定義したプロファイルがある When それを選ぶ Then ロググループ一覧が表示される
- Given SSO のログインが切れている When プロファイルを選ぶ Then ログインが必要なことと次の行動が表示され、アプリは終了しない

### FR2. ロググループの選択（IB-02）

- **FR2.1** アプリは、選んだプロファイル・リージョンで取得できるロググループの一覧を左ペインに表示する（DescribeLogGroups、D-10）。ページングをたどり、すべて表示する。
- **FR2.2** ロググループ一覧は、名前の部分一致で絞り込める（WF 情報構成）。
- **FR2.3** ロググループは一度に 1 つだけ選べる（D-10）。

受け入れ基準：
- Given ロググループが 100 件を超える When 一覧を開く Then すべてのロググループが表示される
- Given 権限がなくロググループを列挙できない When 一覧を開く Then 権限不足であることが文字で表示される

### FR3. 時間範囲の指定とタイムゾーン（IB-03）

- **FR3.1** 開始日時と終了日時を、絶対日時（`yyyy-mm-dd hh:mm:ss`）で入力できる（D-17）。
- **FR3.2** 上部バーで、表示と入力のタイムゾーンを切り替えられる。選択肢は OS のローカルタイムゾーンと UTC の 2 つで、既定はローカル（D-17、レビュー R-03）。
- **FR3.3** タイムゾーンを切り替えても、入力済みの開始・終了日時は同じ瞬間を指したまま表示だけが変わる。ログ一覧の時刻表示も同じく変わり、再取得は不要（D-17、WF タイムゾーン切替）。
- **FR3.4** 次のすべてを満たすときだけ [Fetch] を押せる。満たさないときは押せない状態で、理由を文字で示す（WF [Fetch] の条件）。
  - プロファイルとリージョンが選ばれている
  - ロググループが 1 つ選ばれている
  - 開始日時と終了日時が正しい形式で入力されている
  - 開始日時が終了日時より前である
  - 取得中ではない
- **FR3.5** 終了日時は、その秒の終わりまで（ミリ秒を含めて）を範囲に含む。例：終了 `10:00:00` なら `10:00:00.999` のイベントも含む（レビュー R-03）。
- **FR3.6** ローカルタイムゾーンの夏時間の切り替えで存在しない日時は、入力の誤りとして扱う。2 回現れる日時は、早い方の瞬間として扱う（レビュー R-03）。

受け入れ基準：
- Given ローカル（UTC+9）で開始 `2024-03-01 10:00:00` を入力した When タイムゾーンを UTC に切り替える Then 入力欄は `2024-03-01 01:00:00` と表示され、取得範囲は変わらない
- Given 開始日時が終了日時より後 When 入力する Then [Fetch] は押せず、理由が表示される
- Given 日時が `2024-13-01 00:00:00` のように不正 When 入力する Then [Fetch] は押せず、形式の誤りが表示される
- Given 終了日時 `10:00:00` When 時刻 `10:00:00.999` のイベントがある Then そのイベントは取得・表示される
- Given 終了日時 `10:00:00` When 時刻 `10:00:01.000` のイベントがある Then そのイベントは取得されない

### FR4. ストリームを跨いだ取得と時刻順表示（IB-04）

- **FR4.1** [Fetch] を押すと、選んだロググループのストリームを列挙し（DescribeLogStreams）、指定した時間範囲に関係するストリームから GetLogEvents でログを取得する（C-T1、D-10）。
- **FR4.2** ストリームの最初・最後のイベント時刻で、時間範囲と重ならないストリームを取得対象から外す。最後のイベント時刻は即時に更新されないため、1 時間の余裕を持たせて判定する（RA Q3）。最初・最後のイベント時刻を持たないストリームは、取りこぼしを避けるため取得対象に含める（レビュー R-04）。
- **FR4.3** GetLogEvents は、開始時刻と終了時刻を必ず指定して呼ぶ（C-T4）。
- **FR4.4** ページの終わりは「渡したトークンと同じトークンが返ったとき」で判定する。空のページや部分的なページが返っても、終わりと誤判定しない（C-T2、C-T3）。
- **FR4.5** スロットリングされたときは、待ってから再試行する（C-T5、C-T6）。
- **FR4.6** 時間範囲が広くても件数の上限は設けず、すべて取得する（D-14）。
- **FR4.7** 取得した結果は、取得したものから逐次ログ一覧に加え、常にストリームを跨いだ時刻順に並べて（レビュー R-02）、ログ一覧に「時刻 / ストリーム名 / メッセージ」の列で表示する（D-10、WF 画面 3）。同じ時刻のイベントの並び順は、毎回同じ結果になる決まった順序にする。
- **FR4.8** 取得中は取得条件（プロファイル・リージョン・ロググループ・開始日時・終了日時）を変更できず、[Fetch] は押せない。ステータス行に取得中であることを表示する（D-18、project.md Corrections の状態表示）。
- **FR4.9** 取得中にウィンドウを閉じようとしたときだけ確認ダイアログを出す。[Keep fetching] で取得を続け、[Close] で取得途中の結果を捨てて終了する。取得中でなければ確認なしで閉じる（D-18、WF 画面 7）。
- **FR4.10** 取得の途中でエラー（権限不足・通信断・再試行しても続くスロットリングなど）になったストリームがあっても、取得できた分は表示する。ステータス行に、一部のストリームで取得に失敗したことと、失敗したストリームの数を表示する（RA Q4）。
- **FR4.11** 取得が終わったら、ステータス行に件数を表示する。該当が 0 件のときは、0 件であることを文字で表示する（WF 画面 3、画面 5）。

受け入れ基準：
- Given 3 つのストリームに時刻が交互に並ぶイベントがある When 取得する Then ログ一覧は 3 つのストリームを跨いで時刻順に並ぶ
- Given GetLogEvents が空のページを返したあとに続きのページがある When 取得する Then 続きのページも取得される（空ページで終わらない）
- Given GetLogEvents がスロットリングエラーを返す When 取得する Then 待ってから再試行し、最終的にすべて取得される
- Given 最後のイベント時刻が時間範囲の開始より 2 時間前のストリーム When 取得する Then そのストリームには GetLogEvents を呼ばない
- Given 最後のイベント時刻が時間範囲の開始より 30 分前のストリーム When 取得する Then そのストリームにも GetLogEvents を呼ぶ（余裕の範囲内）
- Given 最初・最後のイベント時刻を持たないストリーム When 取得する Then そのストリームにも GetLogEvents を呼ぶ
- Given 10 ストリーム中 2 ストリームが権限不足で失敗する When 取得する Then 8 ストリーム分の結果が表示され、ステータス行に「2 ストリームで失敗」と表示される
- Given 取得中 When ウィンドウを閉じようとする Then 確認ダイアログが表示される
- Given 取得中 When 一部のストリームの取得が終わる Then 取得済みの分がログ一覧に時刻順で表示され、取得は続く

### FR5. 長いメッセージの表示

- **FR5.1** ログ一覧のメッセージは、1 行に収まる分だけを表示する（WF 画面 3）。
- **FR5.2** 行を押すと、マネジメントコンソールと同じく、その行のすぐ下に全文を展開する。もう一度押すと閉じる。複数の行を同時に展開できる（RA Q6、RA F2）。
- **FR5.3** 展開した全文は選択してコピーできる（RA F2）。
- **FR5.4** MVP では JSON を整形せず、そのまま表示する（RA F2。整形表示は IB-10）。

受け入れ基準：
- Given 5 行からなるメッセージ When 行を押す Then その行のすぐ下に 5 行すべてが表示される
- Given 2 つの行を展開した When もう一方の行を押す Then 両方とも展開されたままになる

### FR6. 部分一致の絞り込み（IB-05）

- **FR6.1** 条件エリアのフィルター入力に文字列を入れると、取得済みのログのうち、メッセージにその文字列を含む行だけを表示する（D-11）。
- **FR6.2** 絞り込みは取得済みのデータに対して手元で行い、AWS の API は呼ばない（feasibility-assessment、D-13）。
- **FR6.3** 絞り込み中は、ステータス行に「絞り込み後の件数 / 全件数」を表示する（WF 画面 4）。
- **FR6.4** 条件を変えて取得し直したとき、入力済みの絞り込み文字列は引き継ぎ、新しい結果にも同じ絞り込みをかける（RA Q7）。
- **FR6.5** 大文字・小文字を区別するかどうかは、Functional Design で決める（下の Open questions）。

受け入れ基準：
- Given 取得済み 10 万件 When 絞り込み文字列を入れる Then 10 秒以内に結果が表示される（NFR1）
- Given 絞り込み文字列 `ERROR` を入れている When 条件を変えて取得し直す Then 新しい結果も `ERROR` で絞り込まれる
- Given どの行にも含まれない文字列 When 絞り込む Then 0 件であることが文字で表示される

### FR7. ディスクキャッシュ（IB-06、Should）

- **FR7.1** 設定ダイアログで、ディスクキャッシュを有効・無効にできる。既定は無効（D-07、D-19、C-R1）。
- **FR7.2** 有効にするとき、保存場所と「ログに機密情報が含まれうる」ことを表示する（WF 画面 6）。
- **FR7.3** 保存場所は OS のキャッシュ用フォルダ（macOS では `~/Library/Caches/` 配下のアプリ専用フォルダ）とし、設定ダイアログに表示する（RA Q8）。
- **FR7.4** キャッシュを使うのは、プロファイル・リージョン・ロググループが一致し、かつ指定した時間範囲がキャッシュ済みの時間範囲に含まれるときとする。含まれる場合は、キャッシュから該当する範囲だけを取り出して表示し、AWS の API は呼ばない（RA Q8）。
- **FR7.5** キャッシュに有効期限は設けない（RA Q8）。
- **FR7.6** 設定ダイアログのキャッシュ削除で、保存したキャッシュをすべて消せる（D-19、RA Q8）。
- **FR7.7** キャッシュが無効のときは、取得したログをディスクに書かない（C-R1）。
- **FR7.8** 期限が厳しいときは、FR7 全体を MVP から外してよい（initiative-brief の削減順）。
- **FR7.9** 失敗したストリームがある取得（FR4.10）と、途中で終了した取得（FR4.9）は、その時間範囲をキャッシュ済みとして記録しない（レビュー R-01）。

受け入れ基準：
- Given キャッシュが有効で、10:00〜12:00 を取得済み When 10:30〜11:00 を指定して [Fetch] Then AWS を呼ばずにキャッシュから表示される
- Given キャッシュが有効で、10:00〜12:00 を取得済み When 09:00〜11:00 を指定して [Fetch] Then AWS から取得する（範囲に含まれないため）
- Given キャッシュが無効 When 取得する Then キャッシュフォルダにファイルが作られない
- Given キャッシュが有効で、取得中に 1 ストリームが失敗した When 同じ条件で [Fetch] Then キャッシュは使わず AWS から取得し直す
- Given キャッシュが有効で、取得中にウィンドウを閉じた When 再起動して同じ条件で [Fetch] Then キャッシュは使わず AWS から取得する
- Given キャッシュがある When キャッシュ削除を実行する Then キャッシュフォルダのファイルがなくなる

### FR8. エラーと入力不備の表示

- **FR8.1** エラーは、何が起きたかと次の行動を文字で示す。生のエラーコードだけを出さない。詳細は短いメッセージとして添える（WF 画面 5）。
- **FR8.2** エラーをアイコンや色だけで示さない（WF 画面 5）。
- **FR8.3** エラー表示とアプリのログには、秘密の認証情報とアクセスキー ID を出さない。プロファイル名・ロール名（ARN）・アカウント ID は出してよい（project.md Forbidden）。
