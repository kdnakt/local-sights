# Requirements — アプリから SSO ログインする

上流：`ideation/intent-capture/intent-statement.md`（意図整理 Q1〜Q6）。この文書の質問は `requirements-analysis-questions.md`（RA Q1〜Q6）。

## 1. 意図の分析

- **何を達成したいか**：SSO が切れても、アプリの画面からログインし直して、ターミナルを開かずに作業を続けられるようにする（意図整理 Q1、Q4）。
- **何に困っているか**：ターミナルとの行き来、ログインし直すプロファイル名を考えて打ち間違えること、切れるたびに作業が止まること、アプリの中で完結しないこと（意図整理 Q1）。
- **誰のためか**：開発者本人（意図整理 Q5）。
- **実現の方式（利用者が指定した前提）**：アプリが手元の AWS CLI の `aws sso login` を起動し、ブラウザでの承認・SSO の API 呼び出し・トークンの保存はすべて CLI が行う。アプリ自身は SSO の API を呼ばず、トークンにも触れない（意図整理 Q2）。この方式は project.md の禁止ルールの対象外であることを、project.md の Corrections に記録済み（意図整理 Q3）。
- **種類と規模**：既存アプリ（Rust のコア＋React/Tauri の画面）への機能追加。コア（プロファイルが SSO かの判定、ログインの状態）、Tauri 側（外部コマンドの起動）、画面（ボタンと待機表示）の 3 層にまたがる。複雑さは Standard。

### 成功指標

| ID | 指標 | 判定方法 | 出典 |
|---|---|---|---|
| SM1 | アプリからの再ログイン | SSO が切れた状態で、画面のエラー表示からログインを始め、ターミナルを開かずに、ロググループの一覧と取得をやり直せる | 意図整理 Q4 |

## 2. 機能要件

### FR1. ログインの入口

- **FR1.1** 認証が必要なエラー（既存の分類 `AuthRequired`）が出たとき、選択中のプロファイルが SSO のプロファイルなら、そのエラー表示の中に「SSO にログイン」ボタンを出す。置き場所は、左ペインのロググループ一覧のエラー表示と、取得全体の失敗のアラートの 2 か所だけとする（RA Q2）。
- **FR1.2** ボタンを押すと、いま上部バーで選んでいるプロファイルでログインする。「デフォルト」を選んでいるときは、プロファイルを指定せずにログインする（RA Q1）。
- **FR1.3** 選択中のプロファイルが SSO のプロファイルでないとき（アクセスキーなど）は、ボタンを出さず、今の文言（プロファイルの設定を確認する案内）のままとする（意図整理 Q6 の「SSO 以外の認証の補助は作らない」）。
- **FR1.4** プロファイルが SSO のものかどうかは、AWS の設定ファイル（`~/.aws/config`）のそのプロファイルに SSO の設定（`sso_session` または `sso_start_url`）があるかで判定する。判定に使うのは「あるかないか」だけで、設定の値は保持しない。
- **FR1.5** 取得中・一覧の読み込み中・ログイン中は、ボタンを押せない。

受け入れ基準：

- Given 選択中のプロファイルが SSO のもので、一覧の読み込みが認証のエラーになった、When 左ペインを見る、Then エラー文言の下に「SSO にログイン」ボタンがある。
- Given 選択中のプロファイルがアクセスキーのもので、認証のエラーになった、When エラー表示を見る、Then 「SSO にログイン」ボタンはない。
- Given 認証以外のエラー（ネットワークなど）になった、When エラー表示を見る、Then 「SSO にログイン」ボタンはない。

### FR2. ログインの実行と待機

- **FR2.1** ボタンを押すと、アプリは AWS CLI の `aws sso login`（プロファイルを指定するときは `--profile <名前>`）を起動する。シェルは通さず、引数はプロファイル名だけとする（意図整理 Q2）。
- **FR2.2** 待っている間は、「ブラウザで承認してください」という案内と、待っていることが分かる表示（処理中の印）を出す（RA Q6、project.md の学び「処理中であることを示す最低限の状態表示を含める」）。
- **FR2.3** CLI が出力した確認コードと URL を画面に出す。ブラウザが自動で開かなかったときに、利用者がその URL を開いてコードを入れられるようにする（RA Q6）。
- **FR2.4** 待っている間は [キャンセル] で止められる。キャンセルすると CLI を終了させ、ログイン前の状態に戻す（RA Q4）。
- **FR2.5** 承認を 5 分待っても終わらない場合は、CLI を終了させ、時間切れとして知らせる（RA Q4）。
- **FR2.6** ログインは同時に 1 つだけ行う。ログイン中は、ほかのログインを始められない。

受け入れ基準：

- Given 「SSO にログイン」を押した、When CLI が承認待ちになった、Then 案内・処理中の印・確認コード・URL・[キャンセル] が出る。
- Given ログインを待っている、When [キャンセル] を押す、Then CLI が終了し、ボタンを押す前の表示に戻る。
- Given ログインを待っている、When 5 分たった、Then CLI が終了し、「時間切れになりました。もう一度ログインしてください」の旨が出る。

### FR3. ログインの結果

- **FR3.1** CLI が成功して終わったら、「ログインしました」と知らせ、ロググループの一覧を自動で読み込み直す（RA Q3）。
- **FR3.2** 取得は自動ではやり直さない。利用者が [取得] を押し直す（RA Q3）。
- **FR3.3** CLI が失敗して終わったら、「ログインできませんでした」の旨と、CLI が出した失敗の理由（秘密情報を除いたもの）を出し、もう一度ボタンを押せる状態に戻す。
- **FR3.4** ログインし直したあと、アプリを再起動しなくても新しい認証情報で一覧と取得ができる。

受け入れ基準：

- Given ログインが成功した、When CLI が終わる、Then 「ログインしました」が出て、一覧の読み込みが自動で始まる。
- Given 取得が認証のエラーで失敗していて、ログインが成功した、When CLI が終わる、Then 取得は自動では始まらず、[取得] を押すと取得できる。
- Given ログインが失敗した、When CLI が終わる、Then 失敗の旨が出て、「SSO にログイン」ボタンをもう一度押せる。

### FR4. AWS CLI が見つからない場合

- **FR4.1** アプリは、AWS CLI を決まった候補の場所から順に探す。候補は少なくとも `/usr/local/bin/aws`（公式のインストーラ）と `/opt/homebrew/bin/aws`（Homebrew）とする。Finder や Dock から起動したアプリにはターミナルの PATH が引き継がれないため、PATH だけには頼らない（RA Q5）。
- **FR4.2** どこにも見つからなければ、「AWS CLI が見つかりません」と、インストールの案内、ターミナルで `aws sso login` を実行する代わりの手順を出す。

受け入れ基準：

- Given AWS CLI がどの候補にもない、When 「SSO にログイン」を押す、Then CLI を起動せず、見つからない旨と代わりの手順が出る。

## 3. 非機能要件

| ID | 種類 | 要件 | 基準 | 出典 |
|---|---|---|---|---|
| NFR1 | セキュリティ | アプリは SSO の API を呼ばず、トークンを読み書きしない | コードに SSO・SSO-OIDC の API 呼び出しと、`~/.aws/sso/cache` の読み書きがない。AWS の API 呼び出しは CloudWatch Logs の 3 つのままである | 意図整理 Q2、Q3、project.md |
| NFR2 | セキュリティ | 外部コマンドの起動を安全に行う | シェルを通さない。起動するのは見つけた `aws` の実行ファイルだけで、引数は `sso login` と、プロファイルを指定するときの `--profile <名前>` だけ。プロファイル名は設定ファイルから読んだ一覧にあるものに限る | FR2.1 |
| NFR3 | セキュリティ | 秘密情報を残さない | CLI の出力をアプリのログ・キャッシュファイルに書かない。画面に出すのは確認コードと URL と失敗の理由だけで、トークン・アクセスキーが含まれる行は出さない | project.md Forbidden |
| NFR4 | 信頼性 | 子プロセスを残さない | キャンセル・時間切れ・アプリの終了のいずれでも、起動した CLI を終了させる | FR2.4、FR2.5 |
| NFR5 | 表示言語 | 英語と日本語 | 新しい文言（ボタン・案内・時間切れ・失敗・CLI が見つからない）を両方の言語で用意する | 既存の方針 |
| NFR6 | 回帰 | 既存の振る舞いを壊さない | 既存の `cargo test` と `vitest` がすべて通る。自動テストは実際の AWS にも、実際の AWS CLI にも接続しない（CLI の起動はテストで差し替える） | team.md Testing Posture、project.md |
| NFR7 | アクセシビリティ | キーボードで操作できる | 「SSO にログイン」と [キャンセル] にキーボードで届き、待機中の状態は文字でも示す | 既存の方針 |

## 4. 制約

| ID | 制約 | 出典 |
|---|---|---|
| CN1 | 実現の方式は AWS CLI の `aws sso login` の起動に限る。アプリ自身による SSO ログインは作らない | 意図整理 Q2、Q6 |
| CN2 | 呼ぶ AWS の API は変えない（DescribeLogGroups・DescribeLogStreams・GetLogEvents）。テレメトリを送らない | project.md Forbidden |
| CN3 | 画面の部品は既存と同じ Cloudscape の部品を使う | 前回の作業の決定 |
| CN4 | 配布の対象は macOS（Apple Silicon） | team.md Deployment |

## 5. 前提

| ID | 前提 | 根拠 | 確かめ方 |
|---|---|---|---|
| AS1 | 会社の Mac には AWS CLI v2 が入っていて、`aws sso login` で SSO のプロファイルにログインできる | 利用者は今もターミナルで `aws sso login` を使っている | 実機での確認 |
| AS2 | `aws sso login` は、承認のための確認コードと URL を標準出力か標準エラーに書き、ブラウザを自動で開こうとする | AWS CLI v2 の振る舞い（開発者の知識。版によって出力の形が違う可能性がある） | 機能設計で出力の形を確かめ、読み取れない場合は案内だけを出す |
| AS3 | SDK はログインし直したあとの新しいトークンを、アプリを再起動しなくても読み直せる | SDK は認証情報が必要になるたびに SSO のトークンのキャッシュを読む（開発者の知識） | 機能設計で、使い回している SDK のクライアントで読み直せるかを確かめ、だめならそのプロファイルのクライアントを作り直す |

## 6. 対象外

- アプリ自身が SSO の API を直接呼んでログインする方式（意図整理 Q6）。
- SSO 以外の認証（アクセスキー、`credential_process` など）のログイン補助（意図整理 Q6）。
- プロファイルの作成や `~/.aws/config` の編集（意図整理 Q6）。
- ログインの状態の監視と、切れる前の通知（意図整理 Q6）。
- 上部バーからのログイン（RA Q2）。
- ログイン後の取得の自動やり直し（RA Q3）。
- ログインするプロファイルを一覧から選ぶ操作（RA Q1）。

## 7. 未決事項

- AWS CLI の候補の場所に、ほかの場所（例：`~/.local/bin`、MacPorts の `/opt/local/bin`）を加えるか。機能設計で決める。
- 確認コードと URL の読み取り方（CLI の出力の形）。機能設計で、版ごとの違いを確かめて決める（AS2）。
