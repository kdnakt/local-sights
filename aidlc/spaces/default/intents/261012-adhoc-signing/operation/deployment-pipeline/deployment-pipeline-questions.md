# Deployment Pipeline Questions — リリースの .app をアドホック署名する

このプロジェクトの「デプロイ」は、GitHub Releases に置いた `.dmg` を会社の Mac に入れる配布のこと（team.md の Deployment）。配布の仕組み（Release ワークフロー）そのものは Code Generation で変更済みで、ブルーグリーンやカナリアのような段階的な配信は対象外。ここでは、残っている配布の決めごとだけを確認する。

いまの状態（GitHub から）：
- 公開済みのリリースは `v0.1.0` だけ（2026-10-12 公開、コミット `9d08cbf`、署名なし）。今回の「壊れている」ダイアログはこの版のもの。
- `main` の先頭はそのコミットと同じで、今回の変更はまだ PR になっていない。

## Q1. 次のリリースの版はどうしますか？

アプリの振る舞いは変わらず、配布の仕組みと手順書だけの変更なので、セマンティックバージョニングではパッチ版が自然です。

- A. `v0.1.1`（パッチ）にする（推奨）
- B. `v0.2.0`（マイナー）にする
- C. Not yet defined
- X. Other (please specify)

[Answer]: A. `v0.1.1`（パッチ）にする

## Q2. 署名付きの版に問題があったとき、どう戻しますか？

team.md の決まりは「前の版の `.dmg` を入れ直す」ですが、前の版 `v0.1.0` は署名なしで、入れ直すと「壊れている」ダイアログが出て `xattr` が要ります。

- A. 決まりどおり前の版の `.dmg` を入れ直す。`v0.1.0` に戻すときだけ `xattr` の予備手順を使うことを戻し方の手順に書く（推奨：戻し先が確実にある）
- B. 署名なしの版には戻さず、直した版をパッチとして出す（前に進むだけ）
- C. Not yet defined
- X. Other (please specify)

[Answer]: B. 署名なしの版には戻さず、直した版をパッチとして出す（前に進むだけ）
