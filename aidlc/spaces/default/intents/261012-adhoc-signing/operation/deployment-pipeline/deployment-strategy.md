# Deployment Strategy — リリースの .app をアドホック署名する

## 方式

**再作成（置き換え）配布**。利用者が新しい `.dmg` を取得し、`Local Sights.app` を「アプリケーション」フォルダで置き換える（team.md の「更新」）。ブルーグリーン、カナリア、ローリング、フィーチャーフラグは、サーバーがなく利用者の Mac 上で動くローカルアプリのため適用しない。段階的な配信は「先に開発者の Mac で確かめてから会社の Mac に配る」という人手の順序で代える。

## 今回の変更が配布に与える影響

| 項目 | 変更前（`v0.1.0`） | 変更後（`v0.1.1` 以降） |
|---|---|---|
| `.app` の署名 | なし | アドホック署名（Apple の証明書なし、公証なし） |
| 初回起動のダイアログ（macOS 15） | 「壊れているため開けません」。GUI では開けず `xattr` が要る | 「Apple は…確認できませんでした」。**完了** → システム設定の **このまま開く** で開ける（想定。実機で確認） |
| ワークフローの検証 | `.dmg` が 1 つであることだけ | 署名の有効性と `Signature=adhoc` も検証。署名がなければ公開しない |
| 利用者の手順書 | `docs/install.md`（旧） | `docs/install.md`（GUI だけの主手順、`xattr` は予備） |

アプリの振る舞い、設定、キャッシュの形式は変わらない。設定とキャッシュは `.app` の外（`~/Library/...`）にあるので、置き換えても残る。

## リリースの手順（`v0.1.1`）

`docs/releasing.md` の手順に従う。要点：

1. 短命ブランチで版を `0.1.1` に上げる（`Cargo.toml`、`npm version 0.1.1 --no-git-tag-version`、`src-tauri/tauri.conf.json`、`cargo update -w`）。`npm run check:version` で確認。
2. 今回の変更（`release.yml`、文書、`scripts/release/signing.*`）と版上げを PR にし、CI がすべて緑になったら `main` にスクワッシュマージする（team.md）。版上げを同じ PR にするか別の PR にするかは開発者の判断。別にする場合も、タグは版上げがマージされた `main` のコミットに打つ。
3. `main` の該当コミットに `v0.1.1` のタグを打って push する。Release ワークフローが署名付きの `.dmg` を公開する。
4. **スモークテスト（配布の成功条件）**：開発者の macOS 15 の Mac で、公開された `.dmg` をブラウザでダウンロードして `/Applications` に入れ、初回起動する。
   - 期待：「Apple は…確認できませんでした」の警告 → **完了** → システム設定 → プライバシーとセキュリティ → **このまま開く** → 再度開くと起動する。ターミナルは使わない。
   - 起動後：**About Local Sights** が `0.1.1` を示し、ログの取得が動く。
   - 「壊れているため開けません」が出たら配布は失敗（`rollback-runbook.md`）。
5. スモークテストが通ってから、会社の Mac に配る（`docs/install.md` を案内する）。

## 中止の条件

- Release ワークフローの署名検証ステップが失敗した：Release は作られていない。原因（`APPLE_SIGNING_IDENTITY` の欠落、Tauri 側の変更）を PR で直し、次のパッチ版でやり直す。
- スモークテストで「壊れている」が出た：公開済みの Release を配らず、`rollback-runbook.md` に従う。
- 会社の MDM が未公証のアプリを拒む：配布を止め、Developer ID と公証の導入を別の作業として検討する（`docs/install.md` の「Before you install」）。

## 確認できないことの扱い

署名ステップの実動作（A2、A3）と Gatekeeper の挙動（A1）は macOS でしか確かめられない。`v0.1.1` のリリースがその最初の実証になる。想定と違えば、結果を `docs/install.md` に反映して次のパッチで直す。
