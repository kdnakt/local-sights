# Functional Design 質問票 — U5 中断（u5-cancel）

上流：`inception/units-generation/unit-of-work.md`（U5、実装の注意：レビュー R-14 の一部）、`unit-of-work-story-map.md`（US3.1、US4.1、US4.2）、`inception/requirements-analysis/requirements.md`（FR5.1〜FR5.11、NFR4、NFR8〜NFR10）、`inception/user-stories/stories.md`（AC3.1.1〜AC3.1.8、AC4.1.1〜AC4.1.6、AC4.2.1）、`inception/domain-design/components.md`・`decisions.md`（ADR-004、ADR-006、ADR-009）、`inception/contract-design/contract-summary.md`（C2 の残した問い、C3、C4、C5、C6、C7）、`inception/refined-mockups/`（画面 A〜D、CancelNotice、文言の一覧）、今のコード（`retry.rs` の StopReason、`schedule.rs` の ScheduleOutcome.unfinished_streams、`coordinator.rs` の decide_job_status、`fetch_status.rs`、`session.rs`、`src/components/`）。

画面の形・文言・注意の出し方・キャッシュに書かないことは、要件と画面の段で利用者と決め終えている。ここで決めるのは止まり方と数え方の細部で、要件から一つに決まるため、新しく利用者に聞くことはない。

## 前提として決めたこと（質問にしない技術的な決め）

- **止まり方（NFR4、ADR-004）**：［中断］は今の止める信号に理由「中断」を送る。出ている GetLogEvents の応答は待ち、届いたページは捨てずに渡す。その後は新しい呼び出しを始めない。再試行の待ち・許可待ちの間なら、すぐに「止めた」で戻る。一覧（DescribeLogStreams）も同じで、出ている呼び出しの応答を待ってから止まる。
- **止めたストリームの状態（契約 C2 の残した問い、レビュー R-14）**：途中で止めたストリームは「止めた」で終える（今の SlotEnd の止めたと同じ）。止めたものと、まだ始めていないものが「読み終えていない」。失敗（あきらめで Skipped にしたものを含む）は含めない。
- **N の数え方（FR5.4）**：N ＝ 止めたストリーム ＋ まだ始めていないストリーム。止めた時点で読み途中だったものは、出ていた呼び出しの応答で最後のページまで読み終えていれば「読み終えた」に入る。
- **終わった扱い（FR5.9）**：止まった時点で N が 0 なら、中断ではなく今の決まりで終わりの状態を決める（Completed か CompletedWithFailures）。注意は出さず、キャッシュの決まりも今と同じ。
- **一覧の前の中断（FR5.6）**：一覧を読み終える前に止めたら、終わりの状態は Cancelled、「一覧の前」の印を立て、N は持たない。読む段は始まらないのでログは 0 件。
- **閉じるが勝つ（ADR-004、FR5.10）**：中断の後に閉じるが来たら Aborted（今と同じく取れたログを捨てて取得前に戻る）。注意は出さない。
- **画面の段階（ADR-009、C5）**：［中断］を受けたら `cancelling` を立てる（段階は取得中のまま）。Cancelled で終わったら段階は Done、取れたログ・件数・失敗の一覧はそのまま、`cancelNotice` を持つ。0 件でも「この範囲にログはありません」は出さない（refined Q3）。
- **中断を押せるか（C5 の fetchCancelAvailable）**：取得中で、中断中でなく、キャッシュに保存中でもキャッシュから表示中でもないときだけ押せる（refined Q2）。
- **注意が消えるとき（FR5.7）**：次の取得を始めたとき、接続（プロファイル・リージョン）を変えたとき、別のロググループを選んだとき。同じロググループを選び直しただけでは消さない（今もログを残す動きに合わせる）。
- **中断のコマンド（C6）**：`cancel_fetch` は何度送っても結果が同じで、押せないときは何もせず成功を返す。Tauri の権限に足す。新しい AWS の呼び出しも外への送信もしない。
- **キャッシュ（FR5.8、C3）**：Cancelled は書かない（今の「Completed かつ失敗 0 だけ書く」のまま）。
- **確認用プログラムと要約の 1 行**：終わりの状態の語に Cancelled が増えるだけ。確認用プログラムは中断を送らない（止まらない信号のまま）。

## Consolidated Summary Confirmation

- ［中断］は止める信号に理由「中断」を送る。出ている呼び出しの応答は待って受け取り、新しい呼び出しは始めない。再試行の待ちや許可待ちの間ならすぐ止まる
- 読み終えていない本数 N は「途中で止めたストリーム」と「まだ始めていないストリーム」の合計。失敗（あきらめたものを含む）は入れない
- 止まった時点で N が 0 なら中断ではなく終わった扱い（注意なし、キャッシュは今の決まりのまま）
- 一覧を読み終える前に止めたら、本数の代わりに「一覧の前」の注意。ログは 0 件
- 中断の後にウィンドウを閉じたら、今と同じく閉じる動きが勝つ
- 中断した後は段階が「終わった」になり、取れたログ・件数・失敗のリンクを残し、注意を出す。0 件でも「この範囲にログはありません」は出さない
- ［中断］を押せるのは取得中で、中断中・キャッシュに保存中・キャッシュから表示中でないときだけ
- 注意は、次の取得を始めたとき・接続を変えたとき・別のロググループを選んだときに消える（同じロググループを選び直しただけでは消えない）
- 中断した取得はキャッシュに書かない。中断のコマンドは何度送っても同じ結果で、エラーを返さない
