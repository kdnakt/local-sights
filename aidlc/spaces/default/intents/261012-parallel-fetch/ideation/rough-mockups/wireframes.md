# Wireframes — ロググループ全体の取得の高速化

上流：`ideation/intent-capture/intent-statement.md`、`ideation/scope-definition/scope-document.md`、`ideation/scope-definition/intent-backlog.md`

## 前提

- 画面の構成は変えない：上の黒いナビゲーション（プロファイル・リージョン・SSO・設定）、左のロググループ一覧、右の条件エリア（日時・タイムゾーン・[Fetch]・ログの絞り込み）、注意やエラーの表示、ログ一覧、ログ一覧の下の状態表示。（rough-mockups Q1）
- 見た目は Cloudscape の標準部品だけを使い、作り込みはしない。（project.md Corrections）
- 今回の画面の変更は 3 つだけ：状態表示に「かかった時間」を足す（B4）、取得中は [Fetch] が [中断] に変わる（B5）、中断した後にログ一覧の上へ注意の表示を出す（B5）。（scope-document、Q1〜Q4）
- 取得を速くすること（B1〜B3）は画面の見た目を変えない。ログが届く速さと順番が変わるだけで、表示は今と同じく時刻順。（scope-document の「変えないもの」）

## 画面 1：取得前（今と同じ）

```
+------------------------------------------------------------------------------+
| Local Sights   [Profile v] [Region v] [SSO]                        [gear]   |
+---------------------+--------------------------------------------------------+
| Log groups          | Start [2026/10/12] [09:00:00]  End [2026/10/12] [10:00:00] |
| [search........]    | (o) Local  ( ) UTC                       [ Fetch ]      |
| > /app/api          | Filter [.................]                              |
|   /app/worker       +--------------------------------------------------------+
|   ...               | Time | Stream | Message                                 |
|                     | (empty)                                                 |
|                     +--------------------------------------------------------+
|                     | (status line: empty)                                    |
+---------------------+--------------------------------------------------------+
```

アクセシビリティ：見出しは今と同じ（h1 は画面名、h2 は各エリア）。主な領域は header（上のナビゲーション）・nav（ロググループ一覧）・main（条件エリアとログ一覧）。キーボードの入口は今と同じく条件エリアの最初の入力欄。

## 画面 2：取得中（変更あり）

```
| Start [2026/10/12] [09:00:00]  End [2026/10/12] [10:00:00]             |
| (o) Local  ( ) UTC                                    [ 中断 ]   <- B5 |
| Filter [.................]                                              |
+------------------------------------------------------------------------+
| Time                | Stream          | Message                        |
| 2026/10/12 09:00:01 | api-7f3a        | GET /health 200                |
| 2026/10/12 09:00:02 | api-91bc        | ...                            |
| ...（届いたページから時刻順に表示）                                       |
+------------------------------------------------------------------------+
| (spinner) Fetching 42 / 180 streams, 12,345 events   経過 00:07  <- B4 |
+------------------------------------------------------------------------+
```

- [Fetch] があった場所に [中断] ボタンを出す。押せる。確認は挟まない。（Q2、Q3）
- 日時・タイムゾーンは今と同じく取得中は変えられない。ログの絞り込みは今と同じく取得中も使える。
- 状態表示の「読み終えたストリーム数 / 読むストリーム数」「イベント数」は今のまま。その後ろに「経過 mm:ss」を足し、取得中は 1 秒ごとに進める。（Q1）
- ストリームの一覧を読んでいる間（読む本数がまだ決まっていない間）も、経過は進める。

アクセシビリティ：[中断] ボタンは [Fetch] と同じ位置・同じタブ順。[Fetch] にフォーカスがあったまま取得が始まった場合、フォーカスは同じ位置の [中断] に残る。状態表示は今と同じく `role="status"`（読み上げは控えめ）。経過の秒が進むたびに読み上げると邪魔になるため、経過の数字は 1 秒ごとの読み上げの対象にしない。

## 画面 3：中断を押した直後（止まるまでの間）

```
| (o) Local  ( ) UTC                                  [ 中断中… ] (押せない) |
...
| (spinner) Stopping…  42 / 180 streams, 12,345 events   経過 00:09        |
```

- 押した後、実際に止まるまでの短い間は、ボタンを「中断中…」にして押せなくする（二度押しの防止）。
- 新しい呼び出しは始めない。すでに出ている呼び出しの結果を待つ間だけの状態。

## 画面 4：中断した後（変更あり）

```
| (o) Local  ( ) UTC                                    [ Fetch ]           |
+--------------------------------------------------------------------------+
| (!) 取得を中断しました。138 本のストリームは読み終えていないため、          |
|     一部のログが含まれていません。                                <- B5 |
+--------------------------------------------------------------------------+
| Time                | Stream          | Message                          |
| （中断までに取れたログを時刻順に表示）                                       |
+--------------------------------------------------------------------------+
| 中断  42 / 180 streams, 12,345 events   経過 00:09                        |
+--------------------------------------------------------------------------+
```

- ボタンは [Fetch] に戻る。取れたログはそのまま表示し、絞り込みも使える。（feasibility Q3）
- ログ一覧の上に注意の表示（Cloudscape の warning の Alert）を出し、読み終えていないストリームの本数を知らせる。（Q4）
- ストリームの一覧を読み終える前に中断した場合は、本数が決まらないため「ストリームの一覧を読み終える前に中断したため、一部のログが含まれていません」と知らせる。
- 中断した取得はキャッシュに残さない。（scope-document の「変えないもの」）
- 注意の表示は、次に取得を始めたとき、または接続（プロファイル・リージョン）やロググループを変えたときに消える。

アクセシビリティ：注意の表示は `role="status"` で一度だけ読み上げる。色だけでなく注意のアイコンと文で伝える。

## 画面 5：取得が終わった後（変更あり）

```
| 12,345 events   経過 00:31                                     <- B4 |
```

- 今の終わりの表示（イベント数、失敗したストリームの件数のリンクなど）はそのまま。その後ろに最終の「経過 mm:ss」を足し、次の取得を始めるまで残す。（Q1）
- 失敗したストリームがある場合の表示（件数のリンクから一覧を開く）は今と同じ。（scope-document の「変えないもの」）
- キャッシュから表示した場合も、かかった時間を出す（AWS を呼ばないので短い時間になる）。

## 状態の一覧

| 状態 | ボタン | 状態表示 | ログ一覧の上 | 出典 |
|------|--------|----------|--------------|------|
| 取得前 | [Fetch] | なし | なし | 今と同じ |
| 一覧を読んでいる | [中断] | 選んだ本数・経過 | なし | Q1、Q2 |
| ストリームを読んでいる | [中断] | 読み終えた本数 / 読む本数・イベント数・経過 | なし | Q1、Q2 |
| 中断中（止まるまで） | [中断中…]（押せない） | Stopping…・経過 | なし | 二度押しの防止 |
| 中断した | [Fetch] | 中断・本数・イベント数・最終の経過 | 注意の表示 | Q4 |
| 終わった（すべて成功） | [Fetch] | イベント数・最終の経過 | なし | Q1 |
| 終わった（一部失敗） | [Fetch] | イベント数・失敗の件数のリンク・最終の経過 | 今と同じ | 今と同じ |
| 失敗した | [Fetch] | 今と同じ | 今と同じエラーの表示 | 今と同じ |
| 0 件 | [Fetch] | 「0 events」・最終の経過 | なし | 今と同じ |

## 画面の構成（情報のまとまり）

- 上のナビゲーション：接続（変更なし）
- 左：ロググループ一覧（変更なし）
- 右上：条件エリア。[Fetch] / [中断] の切り替えはここ
- 右中：注意・エラーの表示（中断の注意を追加）、ログ一覧（変更なし）
- 右下：状態表示（経過を追加）

## Assumptions & Open Questions

- [assumption] 中断を押してから実際に止まるまでの間は、「中断中…」で押せない状態にする（二度押しの防止のため。質問では決めていない）
- [assumption] ストリームの一覧を読み終える前の中断は、本数の代わりに「一覧を読み終える前に中断した」と知らせる
- [assumption] 中断の注意の表示は、次の取得や接続・ロググループの変更で消える
- [assumption] 経過の表示は「経過 mm:ss」とし、1 時間を超える場合は h:mm:ss とする
