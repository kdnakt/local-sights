### 前回の指摘の状態

ゲートでの Request Changes のもとになった前回のアドバイザリーレビューの指摘 R-01 から R-07 の反映状況は次のとおり。R-01（SDK の既定の再試行）は Fixed。再試行をアプリ側に一本化する方針が ADR-008、AwsCloudWatchLogsGateway、CallPacer の記述にそろって書かれた。R-02（宣言された依存と実際の依存の食い違い）は Partially fixed。CachePlan と FetchCoordinator の相互の依存は、JobStatus を FetchStatus に出して解けた（plan.rs が coordinator から取り込むのは JobStatus だけであることをコードで確認）。AppSession の依存も宣言され、値だけの参照と型の依存の区別も付いた。ただし新しい部品どうしの型の依存の漏れが残る（下の新規指摘 1 と 3）。R-03（止める理由の優先）は Fixed。「閉じる」が常に勝つ、で components.md と ADR-004 が食い違いなく書かれた。R-04（終わりの状態の持ち主）は Partially fixed。Cancelled が加わり、Aborted との違いと StreamSchedule だけが決める形が書かれたが、一覧の失敗と一覧の前の中断では成り立たない（新規指摘 2）。R-05（max_consecutive_exhausted と StreamEnding の置き場）は Partially fixed。持ち主は StreamSchedule に決まったが、依存の向きが宣言されていない（新規指摘 1）。R-06（リージョンの取り方）は Fixed。`FetchRequest.region()` が `None` のときは表にないリージョンと同じ 1 秒 5 回程度にすると書かれた。R-07（FetchCheck、RecordingSink、NFR5、ページの通り道）は Fixed。FetchCheck と RecordingSink が部品に加わり、NFR5 は既存の速度測定テストで確かめる対象として明記され、通り道を上限のある形にするかは機能設計に送ると Assumptions に書かれた。
