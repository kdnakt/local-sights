# Mockups — ロググループ全体の取得の高速化

上流：`ideation/rough-mockups/wireframes.md`・`user-flow.md`、`inception/user-stories/stories.md`、`inception/requirements-analysis/requirements.md`、`inception/practices-discovery/team-practices.md`。

画面の構成は今と同じ（上の黒いナビゲーション、左のロググループの表、右の条件エリア、注意とエラーの表示、ログの表、表の下の状態表示）。変わるのは、条件エリアの右上のボタン、状態表示の末尾、ログの表の上の注意の 3 か所だけ（wireframes「前提」）。デスクトップアプリなので、画面幅による切り替えは扱わない。文言は英語と日本語の両方を用意し、OS の言語で出し分ける（NFR9）。下の図は日本語の場合。

## 画面 A：取得中（US1.1・US1.2・US2.1・US3.1）

```
┌─ 条件エリア（Container） ───────────────────────────────────────────┐
│ /app/api                                              [ 中断 ]  ←①  │
│ 開始（ローカル） [2026/10/12] [09:00:00]   終了 [2026/10/12] [10:00:00] │
│ ( ) UTC  (●) ローカル          ログの絞り込み [..................]   │
├─────────────────────────────────────────────────────────────────────┤
│ 時刻                 │ ストリーム   │ メッセージ                      │
│ 2026/10/12 09:00:01 │ api-7f3a     │ GET /health 200                  │
│ 2026/10/12 09:00:02 │ api-91bc     │ ...（届いた分から時刻順）          │
├─────────────────────────────────────────────────────────────────────┤
│ ◌ 取得中… 42/180 ストリーム、これまでに 12,345 件   経過 00:07   ←②  │
└─────────────────────────────────────────────────────────────────────┘
```

- ① ［取得］（Fetch）が同じ場所で［中断］（Cancel）に変わる。見た目は［取得］と同じ主ボタン（primary）。押すと確認なしで止め始める（FR5.1、rough-mockups Q2・Q3）。
- ② 今の状態表示の文言はそのまま。末尾に「経過 mm:ss」を足す。取得中は 1 秒ごとに進み、再試行の待ちの間も進む（FR4.1・FR4.2）。
- ストリームの一覧を読んでいる間は、今の「ストリームを列挙中… これまでに n ストリームを対象にしました」の後ろに経過を足す（wireframes 画面 2）。

## 画面 B：中断中（押してから止まるまで）（US3.1）

```
│ /app/api                                       [ ◌ 中断中… ]  ←③   │
...
│ ◌ 取得中… 42/180 ストリーム、これまでに 12,345 件   経過 00:09        │
```

- ③ Cloudscape のボタンの「読み込み中」の状態（回る印と「中断中…」）。押しても何も起きない。フォーカスはボタンに残る（refined Q1、FR5.2）。
- 新しい呼び出しは始めない。出ている呼び出しの応答を待つ間だけの状態。
- 止まったら［取得］に戻り、画面 C になる。

## 画面 C：中断した後（US4.1・US4.2）

```
│ /app/api                                              [ 取得 ]       │
├─────────────────────────────────────────────────────────────────────┤
│ ⚠ 取得を中断しました。138 本のストリームは読み終えていないため、     │
│   一部のログが含まれていません。                                ←④   │
├─────────────────────────────────────────────────────────────────────┤
│ （中断までに取れたログを時刻順に表示。絞り込みも使える）                 │
├─────────────────────────────────────────────────────────────────────┤
│ 中断  12,345 件   2 ストリームで失敗 [失敗の詳細を見る]   経過 00:09 ←⑤ │
└─────────────────────────────────────────────────────────────────────┘
```

- ④ ログの表の上に注意（Cloudscape の Alert、type="warning"）。本数 N は「読み途中」と「まだ始めていない」の合計で、失敗は含めない（FR5.4、RA Q4）。
- ⑤ 状態表示は「中断」、件数、（あれば）今と同じ失敗の件数と詳細のリンク、最終の経過。中断と一部失敗が重なったら、④と失敗のリンクの両方を出す（FR5.5）。
- 中断した取得はキャッシュに残さない（FR5.8）。
- 注意は、次の取得を始めたとき、接続かロググループを変えたときに消える（FR5.7）。

### 画面 C のちがい

| 場合 | ④ 注意の文 | ⑤ 状態表示 | 出典 |
|------|------------|------------|------|
| ストリームの一覧を読み終える前に中断 | 「ストリームの一覧を読み終える前に中断したため、一部のログが含まれていません。」 | 中断・件数・経過 | FR5.6 |
| 1 件も取れないうちに中断 | ④ と同じ（本数つき、または一覧の前の文） | 「中断」「0 件」・経過。「この範囲にログはありません」は出さない | refined Q3 |
| 最後のストリームを読み終えた直後に中断が届いた | 出さない（終わった扱い） | 画面 D と同じ | FR5.9 |

## 画面 D：取得が終わった後（US2.1）

```
│ 12,345 件   経過 00:31                                              │
│ 12,345 件   2 ストリームで失敗 [失敗の詳細を見る]   経過 00:31          │
│ 0 件：この範囲にログはありません。   経過 00:02                        │
```

- 今の終わりの表示はそのまま。末尾に最終の経過を足し、次の取得まで残す（FR4.3）。
- キャッシュから表示した場合も経過を出す（FR4.4）。

## 画面 E：キャッシュに保存中（Q2）

```
│ /app/api                                          [ 中断 ]（押せない）│
...
│ ◌ キャッシュに保存中   経過 00:30                                      │
```

- 全ストリームが成功してキャッシュに保存している間は、［中断］を押せない（Cloudscape の disabled）。保存が終わったら［取得］に戻る（refined Q2）。
- キャッシュから表示する間も同じ扱い（ほぼ一瞬で終わる）。

## 状態と見た目の対応

| 状態 | ボタン | 状態表示（日本語） | 表の上 | ストーリー |
|------|--------|--------------------|--------|------------|
| 取得前 | ［取得］（条件がそろえば押せる） | 今と同じ | なし | — |
| 一覧を読んでいる | ［中断］ | 列挙中…＋経過 | なし | US3.1、US2.1 |
| ストリームを読んでいる | ［中断］ | 取得中…＋経過 | なし | US1.1、US2.1 |
| 中断中 | ［◌ 中断中…］（読み込み中） | 取得中…＋経過 | なし | US3.1 |
| キャッシュに保存中 | ［中断］（押せない） | キャッシュに保存中＋経過 | なし | refined Q2 |
| 中断した | ［取得］ | 中断・件数・（失敗）・最終の経過 | 中断の注意 | US4.1 |
| 終わった | ［取得］ | 今と同じ＋最終の経過 | 今と同じ | US2.1 |
| 失敗した | ［取得］ | 今と同じ＋最終の経過 | 今と同じエラー | US2.1 |
