# Requirements — ロググループ全体の取得の高速化

上流：`ideation/intent-capture/intent-statement.md`、`ideation/scope-definition/scope-document.md`、`ideation/feasibility/`、`ideation/rough-mockups/`、`inception/practices-discovery/team-practices.md`、コードの知識ベース `aidlc/spaces/default/codekb/local-sights/`（business-overview.md、architecture.md、code-structure.md）。質問と回答は `requirements-analysis-questions.md`（以下 RA Qn）。

## 1. 意図の分析

- **ねらい**：ストリームが数十〜数百本あるロググループで短い時間範囲を取得するとき、待ち時間を短くする（intent-statement）。今のアプリはストリームを 1 本ずつ順に読むため、本数に比例して待つ（architecture.md の Data Flow 5）。
- **あわせて**：取得の進み具合に「かかった時間」を足し、利用者が取得を途中で止められるようにする（scope-document の B4・B5）。
- **種類と規模**：既存アプリの機能拡張。取得の中核（ライブラリ）・アプリのつなぎ・画面の 3 層にまたがる。複雑さは標準。深さは Standard。
- **守るもの**：呼べるのは読み取りの 3 つの呼び出しだけ。同じ AWS アカウントの他の利用者のために、呼び出しの量は上限の半分程度に抑える（feasibility Q2）。

### FR5 取得を中断できるようにする（B5）

## 4. 制約

- 呼べるのは DescribeLogGroups / DescribeLogStreams / GetLogEvents だけ（project.md Forbidden）。
- ログを読む呼び出しの上限はアカウントとリージョンごとに共有され、引き上げを申請できない（feasibility C-T2）。
- ストリームの一覧は 1 ページずつ順にしか読めない（feasibility C-T4）。
- 期限は 1 週間。収まらないときは、まず中断（FR5）、次にかかった時間の表示（FR4）を外す。FR1〜FR3 と FR6 は外さない（scope Q2、RA Q5）。
- 画面は Cloudscape の標準部品だけを使う（project.md Corrections）。
- 自動テストと CI から実際の AWS に接続しない。CI に AWS の認証情報を置かない（project.md Forbidden）。

## 5. 前提

| 前提 | 理由 |
|------|------|
| 待ち時間の大半は、呼び出しを順に待つ時間である | 困りごとの場面では 1 本あたりの呼び出しが少ないため（feasibility A-01）。NFR1 で偽物を使って確かめる |
| 利用者のふだんのリージョンは東京 | feasibility Q1 |
| 取得の部品（受け口や件数の集計）は、今は 1 本ずつ読む前提で作られており、同時に読める形に変える必要がある | architecture Improvement Opportunities |
| ストリームの一覧と取得を重ねる（一覧の途中から読み始める）かどうかは、機能設計で決める。要件は「一覧の後に読む」今の順でも満たせる | 困りごとの場面では一覧は数ページで済むため（feasibility の評価） |
