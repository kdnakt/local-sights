# Personas — ロググループ全体の取得の高速化

人物は 1 人にまとめる（user-stories-questions Q1）。今回の変更（速さ、かかった時間、中断）では、開発者本人・同じ会社の同僚・OSS の利用者の困りごとはほぼ同じため。

## P1 ストリームの多いロググループを調べる人

| 項目 | 内容 |
|------|------|
| 役割 | 自分の AWS 認証情報で CloudWatch Logs のログを読み、障害や動きを調べる開発者・運用担当者（business-overview） |
| 含む利用者 | 開発者本人（作る人でもある）、同じ会社でこのアプリを使う同僚、OSS としてこのアプリを使う不特定の利用者（intent-statement の Target Customer） |
| 目的 | ストリームが数十〜数百本あるロググループで、短い時間範囲のログを待たずに見る。必要なログが見えたら、それ以上待たずに先へ進む |
| 困りごと | 今はストリームを 1 本ずつ読むため、本数に比例して待たされる。どれだけ待ったかが分からない。取得を途中で止められない（intent-statement、rough-mockups） |
| 気にしていること | 同じ AWS アカウントを使う他の人やシステムを待たせないこと（少し気にする、多少は許される）（intent-capture Q5） |
| 使い方 | 主に会社の Mac（Apple Silicon）、ふだんは東京リージョン。OSS の利用者は他のリージョンも使う（feasibility Q1、requirements FR2.2） |
| 技術への慣れ | 高い。AWS の用語やロググループ・ストリームを理解している |
| 頻度 | 調べものがあるたびに、1 日に何度も取得する |

## 関係と優先

人物は 1 人のため、優先の順位はない。開発者本人は作る人でもあるが、CI のカバレッジの下準備（FR6）は利用者のストーリーにしない（user-stories-questions Q3）。
