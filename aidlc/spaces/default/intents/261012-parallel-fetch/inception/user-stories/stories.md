# User Stories — ロググループ全体の取得の高速化

人物：P1 ストリームの多いロググループを調べる人（personas.md）。分け方は利用者の流れ：取得を始めて速く見る（US1）→ 待っている間の様子を見る（US2）→ 途中で止める（US3）→ 止めた後の画面を見る（US4）（user-stories-questions Q2）。優先度は MoSCoW。範囲の決定で B1〜B5 はすべて Must（scope-document）。CI のカバレッジの下準備（FR6）はストーリーにしない（Q3）。

## US1 取得を始めて、速く見る

### US1.1 ストリームの多いロググループを速く取得する

P1 として、ストリームが数十〜数百本あるロググループを取得したとき、全件が今より速くそろってほしい。なぜなら、待たずに調べものを進めたいから。

- 優先度：Must（B1）
- 要件：FR1.1、FR1.4、NFR1、NFR2

| ID | 受け入れ基準 |
|----|--------------|
| AC1.1.1 | Given ストリームが 2 本以上選ばれている When 取得を始める Then 2 本以上のストリームのログを読む呼び出しが、前の呼び出しの終わりを待たずに出ている |
| AC1.1.2 | Given AWS の代わりの偽物（1 回の呼び出しに一定の時間がかかる）とストリーム 100 本・各 1 回の呼び出し When 取得する Then 全件がそろうまでの時間は、1 本ずつ読む場合の半分以下である（偽物の時間と上限の条件は要件の未解決事項と機能設計で確定する） |
| AC1.1.3 | Given 同じロググループと時間範囲 When 取得する Then 選ばれるストリームは今と同じ |
| AC1.1.4 | Given 実際の AWS で困りごとの場面のロググループ When 本人が取得する Then 状態表示の「かかった時間」で速さを確かめられる |

### US1.2 届いた分から時刻順に見え始める

P1 として、全件がそろう前でも、届いたログから時刻順に見たい。なぜなら、最初の数件で原因が分かることが多いから。

- 優先度：Must（B1）
- 要件：FR1.2、FR1.3、NFR5

| ID | 受け入れ基準 |
|----|--------------|
| AC1.2.1 | Given 取得中 When 最初のページが届く Then その行がすぐ一覧に出る |
| AC1.2.2 | Given 古い時刻のページが新しいページより後に届く When 一覧を見る Then 時刻・ストリーム名・順番の順に並んでいる |
| AC1.2.3 | Given 100 万件のログ When 同時に読んで古いページが後から届く Then 一覧は今と同じ速度測定の基準でなめらかに動く |
| AC1.2.4 | Given 取得中 When 1 件目が出るまでの時間を偽物で測る Then 1 本ずつ読む場合より短い |

### US1.3 一部のストリームが失敗しても、取れた分を見る

P1 として、一部のストリームが失敗しても、他のストリームのログは見たい。なぜなら、全部そろわなくても調べられることが多いから。

- 優先度：Must（B1）
- 要件：FR1.5、NFR8

| ID | 受け入れ基準 |
|----|--------------|
| AC1.3.1 | Given 1 本のストリームが失敗する When 取得が終わる Then 他のストリームのログが表示され、今と同じ失敗の件数のリンクが出る |
| AC1.3.2 | Given 失敗の一覧を開く When 失敗の理由を見る Then 秘密の認証情報とアクセスキー ID は出ていない |

## US2 待っている間の様子を見る

### US2.1 取得にかかった時間を見る

P1 として、取得中と取得後に、かかった時間を見たい。なぜなら、どれだけ待っているか、速くなったかを知りたいから。

- 優先度：Must（B4。期限が厳しいときは 2 番目に外す）
- 要件：FR4.1、FR4.2、FR4.3、FR4.4、FR4.5、FR4.6、NFR9

| ID | 受け入れ基準 |
|----|--------------|
| AC2.1.1 | Given 取得中 When 状態表示を見る Then 読み終えた本数 / 読む本数、イベント数、経過が並んでいる |
| AC2.1.2 | Given 取得中に 16 秒の再試行の待ちに入る When 待っている Then 経過は 1 秒ごとに進み続ける |
| AC2.1.3 | Given 取得が成功・一部失敗・失敗・中断のどれかで終わった When 状態表示を見る Then 最終の経過が、次の取得を始めるまで残っている |
| AC2.1.4 | Given ディスクキャッシュに当たる When 表示が終わる Then 経過が出ている |
| AC2.1.5 | Given 経過が 75 分 When 表示する Then 「1:15:00」と出る。1 時間未満は「mm:ss」 |
| AC2.1.6 | Given OS の言語が英語 / 日本語 When 状態表示を見る Then 経過の文言がその言語で出る |
| AC2.1.7 | Given 画面の読み上げを使っている When 経過が進む Then 1 秒ごとには読み上げない |

### US2.2 同じアカウントの他の人を待たせない

P1 として、速く取得しても、同じ AWS アカウントでログを読む他の人やシステムを待たせたくない。なぜなら、共有のアカウントで迷惑をかけたくないから。

- 優先度：Must（B2）
- 要件：FR2.1、FR2.2、FR2.3、FR2.4、FR2.5、FR2.6、NFR3

| ID | 受け入れ基準 |
|----|--------------|
| AC2.2.1 | Given 東京リージョン（上限 1 秒 25 回） When 取得する Then ログを読む呼び出しは、再試行を含めて 1 秒あたり 12 回程度を超えない |
| AC2.2.2 | Given 上限の表にないリージョン When 取得する Then 1 秒あたり 5 回程度を超えない |
| AC2.2.3 | Given 制限の応答が続く When 取得を続ける Then 呼び出しの間隔が広がり、しばらく制限を受けなければ元に戻る |
| AC2.2.4 | Given 1 回の呼び出しが制限を受ける When 再試行する Then 待ちは今と同じ 1・2・4・8・16 秒 ±20%、最大 5 回 |
| AC2.2.5 | Given AWS SDK の中の再試行 When 呼び出しを数える Then SDK の中の再試行も数に入っている（数えられない再試行が重ならない） |
| AC2.2.6 | Given 引き下がっている When 状態表示を見る Then 取得中の表示だけで、特別な表示は出ない |

### US2.3 制限を受け続けたら、無駄に待たずにあきらめる

P1 として、制限を受け続けているときは、残りのストリームを延々と待たずに失敗として知りたい。なぜなら、時間をおいてやり直すか判断したいから。

- 優先度：Must（B3）
- 要件：FR3.1、FR3.2、FR3.3、FR3.4

| ID | 受け入れ基準 |
|----|--------------|
| AC2.3.1 | Given 再試行を使い切ったストリームが 2 本終わった後に成功が 1 本終わる When 次に使い切りが 1 本終わる Then 使い切りの数は 1 |
| AC2.3.2 | Given 使い切りが 3 本たまった When まだ読み始めていないストリームが残る Then それらは呼ばれず、最後に使い切ったストリームの失敗の内容で失敗の一覧に入る |
| AC2.3.3 | Given 使い切りが 3 本たまった When 読み途中のストリームがある Then そのストリームは最後まで読む |
| AC2.3.4 | Given 使い切り 2 本の後に権限のエラー（再試行しない失敗） When 数える Then 数は 0 に戻る |

## US3 途中で止める

### US3.1 取得を途中で止める

P1 として、必要なログが見えたら、取得を途中で止めたい。なぜなら、残りを待つ必要がないから。

- 優先度：Must（B5。期限が厳しいときは最初に外す）
- 要件：FR5.1、FR5.2、FR5.9、FR5.10、NFR4、NFR9、NFR10

| ID | 受け入れ基準 |
|----|--------------|
| AC3.1.1 | Given 取得中 When 画面を見る Then [Fetch] があった場所に [中断]（英語では Cancel）がある |
| AC3.1.2 | Given 取得中 When [中断] を押す Then 確認は出ず、すぐ止め始める |
| AC3.1.3 | Given [中断] を押した When 止まるまで Then ボタンは「中断中…」で押せず、新しい呼び出しは 1 回も始まらない |
| AC3.1.4 | Given 再試行の待ちの間に [中断] を押す When 結果を見る Then すぐに止まる |
| AC3.1.5 | Given 止まった When ボタンを見る Then [Fetch] に戻り、フォーカスはボタンのままである |
| AC3.1.6 | Given 最後のストリームを読み終えた直後に [中断] が届く When 結果を見る Then 中断ではなく、終わった状態になる |
| AC3.1.7 | Given 取得中 When ウィンドウを閉じる Then 今と同じ確認が出て、閉じると取得を止めて終了する |
| AC3.1.8 | Given キーボードだけで操作する When Tab で移動する Then [中断] は [Fetch] と同じ順にあり、押せる |

## US4 止めた後の画面を見る

### US4.1 取れた分を見て、足りない分を知る

P1 として、中断した後も取れたログを見て、何が足りないかを知りたい。なぜなら、全部そろったと誤解したくないから。

- 優先度：Must（B5）
- 要件：FR5.3、FR5.4、FR5.5、FR5.6、FR5.7、FR5.11、NFR8、NFR9

| ID | 受け入れ基準 |
|----|--------------|
| AC4.1.1 | Given 中断した When 一覧を見る Then 取れたログが時刻順に出ていて、絞り込みも使える |
| AC4.1.2 | Given 180 本中 40 本成功・2 本失敗・5 本読み途中・133 本未着手で中断した When 注意を見る Then 「138 本のストリームは読み終えていないため、一部のログが含まれていません」と出る |
| AC4.1.3 | Given 上の例 When 画面を見る Then 中断の注意と、「失敗 2 本」のリンクの両方が出ている |
| AC4.1.4 | Given ストリームの一覧を読み終える前に中断した When 注意を見る Then 「ストリームの一覧を読み終える前に中断したため、一部のログが含まれていません」と出る |
| AC4.1.5 | Given 中断の注意が出ている When 次の取得を始める、または接続かロググループを変える Then 注意は消える |
| AC4.1.6 | Given 画面の読み上げを使っている When 中断した Then 注意が一度だけ読み上げられ、色だけでなくアイコンと文で伝わる |

### US4.2 中断した取得はキャッシュに残らない

P1 として、中断した取得の結果が、後で完全な結果のように使われないでほしい。なぜなら、足りないログを見落としたくないから。

- 優先度：Must（B5）
- 要件：FR5.8

| ID | 受け入れ基準 |
|----|--------------|
| AC4.2.1 | Given ディスクキャッシュが有効で中断した When 同じ範囲をもう一度取得する Then キャッシュは使われず、AWS から読む |

## 依存関係

- US1.2・US1.3・US2.1〜US2.3・US3.1 は、同時に読む形（US1.1）を前提にする。
- US4.1・US4.2 は、中断（US3.1）を前提にする。
- 作業の順番：下準備（CI のカバレッジ、FR6）→ US1.1 を中心にした薄い一本 → 残り（requirements FR6.4）。

| ストーリー | 確認 |
