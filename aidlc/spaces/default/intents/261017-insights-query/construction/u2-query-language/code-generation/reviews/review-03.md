### Summary

The three console-confirmed rules are implemented consistently. `limit 0` keeps no rows, and `has_row_limit` stops the default 10,000 cut from applying. `truncated_at` is None when no rows remain, so the frontend "Showing N" notice and the `(shown / matched)` counter in `resultCount` do not appear. `matchedCount` keeps its R-08 meaning. A missing field on either side of a field-to-field comparison matches nothing, while BR1.5 for a field against a value is unchanged. `<`, `<=`, `>` and `>=` between strings never match unless both read as numbers. No `unwrap` or `expect` was added outside tests, and the new tests cover the checked and the provisional cases separately, in both directions and around a filter. `runner.rs` and the session view only receive a smaller row set and never read the limit. The only remaining finding in app code is a stale comment, plus a misleading empty-state message. Note, not counted against U2: `examples/compat_check.rs` (U4) still describes `limit 0` as "no limit, cap 10,000"; both sides yield 0 rows, so it is harmless.
