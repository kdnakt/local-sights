# Accessibility Checklist — Logs Insights 互換のクエリ（IB-11）

上流：`inception/requirements-analysis/requirements.md`（NFR9 表示言語、NFR10 キーボード操作、NFR11 標準部品）、`mockups.md`、`interaction-spec.md`。目標は WCAG 2.1 AA の考え方に沿うこと。今の画面（261010-console-ui-polish）と同じ水準を保つ。

| 確認 | 中身 | 画面 |

## 読み上げ（スクリーンリーダー）

| 確認 | 中身 |
|---|---|
| [ ] すべての欄に見えるラベル | Log groups、Start、End、Query。プレースホルダだけに頼らない |
| [ ] 画面の切り替えを知らせる | 切り替えたら画面名を `aria-live="polite"` で読み上げる |
| [ ] 実行の段階を知らせる | 取得中・実行中・完了（件数）・0 件・止めた、を `aria-live="polite"` で読み上げる。進みの数は細かく読み上げすぎない（今の Log events と同じ間引き） |
| [ ] エラーを知らせる | 書き間違い・対応外のエラーの文を `aria-live="assertive"` で読み上げ、焦点をクエリ欄の該当の場所に置く |
| [ ] 欄の不備を欄に結びつける | FormField の errorText を欄の説明（`aria-describedby`）として結びつける |
| [ ] 結果の表 | 列の見出しを表の見出しとして持つ。行を開いたことを `aria-expanded` で伝える |
| [ ] 選んだロググループ | トークンの × に「{名前} を外す」のラベル |

## 色とコントラスト

| 確認 | 中身 |
|---|---|
| [ ] 色だけで伝えない | エラーは赤い下線に加えて行番号の横の印（アイコン）と直下の文字。今の画面のナビゲーション項目は太字と `aria-current` も付ける |
| [ ] 構文の色分けは補助 | 色分けがなくても意味は失われない（FR9.2） |
| [ ] コントラスト | 文字 4.5:1、部品 3:1。Cloudscape のトークンと、明暗それぞれの Ace のテーマで確かめる |
| [ ] 明暗モード | OS の設定に合わせ、クエリ欄も同じに切り替わる |

## 確かめ方

- 自動：画面側のテスト（Vitest と Testing Library）で、ラベル、`aria-*`、Tab の順、キーの組み合わせ（macOS と Windows の両方の判定）を確かめる。
- 手で：macOS では VoiceOver、Windows では ナレーター で、主な流れ（画面 2〜5）とエラー（画面 7）を読み上げで確かめる。キーボードだけで主な流れを終えられることを両方の OS で確かめる（team.md Walking Skeleton の手元の確認に合わせて行う）。
