# Mockups — Logs Insights 互換のクエリ（IB-11）

上流の成果物：`inception/requirements-analysis/requirements.md`（FR1〜FR9、NFR9〜NFR11、A1〜A5）。ラフな画面設計（wireframes・user-flow）はこの計画では作っていないため、要件と今の画面（261010-console-ui-polish の mockups.md、今の `src/App.tsx`）から起こした。質問票の回答は `refined-mockups-questions.md` の Q1〜Q5。2026-10-17 の要件の見直し（RA Q3b：2 つの画面は取得済みのログを共有しない）に合わせて、画面 4 の注記と補完の候補元を直した。

ここで決めたこと：

| 論点 | 決めたこと | 出典 |
|---|---|---|
| 2 つの画面の切り替え | 左端に細いナビゲーション（SideNavigation）を置き、「Log Management」「Log Analytics」で切り替える（名前は今のコンソールに合わせる。クエリの言語はコンソールと同じ Logs Insights のクエリ） | Q1、FR1.1 |
| クエリの画面でのロググループの選び方 | クエリ欄の上の複数選択のドロップダウン（Multiselect、名前で探せる）。左ペインのロググループの表はクエリの画面には出さない | Q2、FR1.3 |
| クエリ欄 | 最初からコードの欄（CodeEditor）。色分けと補完（FR9、Should）はこの欄に載せる | Q3 |
| 結果の行を開いたとき | 項目と値の一覧（メッセージ全体も一覧の 1 行） | Q4、FR7.4 |
| エラーの出し方 | クエリ欄の直下に文字で出し、欄の中の該当する場所にも印を付ける | Q5、FR6 |

図は英語の仮ラベル（日本語表示の文言は interaction-spec.md の文言表のとおり）。`<...>` は Cloudscape の部品名。

## 画面 1：Log Management（今のログの画面）とナビゲーション

```
+------------------------------------------------------------------------------------------+
| # local-sights                     Profile: default v | ap-northeast-1 v | Local v | (*) |  <TopNavigation>
+------+-----------------------------------------------------------------------------------+
| Log  | +-- Log groups ---------------+ +-- /aws/lambda/app-b ------------- [Fetch] -----+ |
| events| | [q Find log groups      ]  | | [q Filter events   ] Start [....] End [....]   | |
| >    | | ( ) /aws/lambda/app-a       | | +-------------------------------------------+ | |
|      | | (o) /aws/lambda/app-b       | | | Timestamp (Local) | Stream | Message      | | |
| Log  | | ...                         | | | ...                                       | | |
| Analytics| [Reload]                  | | +-------------------------------------------+ | |
|      | +-----------------------------+ +-----------------------------------------------+ |
+------+-----------------------------------------------------------------------------------+
| 128,431 events                                                                           |  status line
+------------------------------------------------------------------------------------------+
```

- 左端のナビゲーション（Q1、FR1.1）：`<SideNavigation>` に 2 項目「Log Management」（日本語表示は「ログ管理」）「Log Analytics」。名前は今のコンソールの左のナビゲーションに合わせる（AWS の資料では、ロググループを開く項目は「Log Management」）。今いる画面の項目を強調する（色だけでなく太字と `aria-current="page"`）。幅は約 10rem。
- ナビゲーションは閉じられる（コンソールと同じ）。見出しの右の [×]（閉じる）で閉じると、左端に細い帯と [≡]（開く）だけが残り、内容の幅が広がる。[≡] で元に戻す。開いているか閉じているかは、アプリを閉じるまで覚えておく（画面 1b）。
- 上部ナビゲーション（プロファイル・リージョン・タイムゾーン・設定）は 2 つの画面で共通。接続を変えたときの扱いは今と同じ（A2）。
- Log Management の中身は今のまま変えない（FR1.8、C5）。ナビゲーションの分だけ左に寄る。
- ステータス行は今いる画面の内容を出す（Log Management なら今と同じ）。

## 画面 2：Log Analytics（クエリの画面、初めて開いたとき）

```
+------------------------------------------------------------------------------------------+
| # local-sights                     Profile: default v | ap-northeast-1 v | Local v | (*) |
+------+-----------------------------------------------------------------------------------+
| Log  | +-- Log Analytics ---------------------------------------------------------------+ |
| events| | Log groups                                                                    | |
|      | | [ Select log groups (up to N)                                        v ]      | |  <Multiselect filteringType="auto">
| Log  | | Start (Local) [yyyy/mm/dd|v] [hh:mm:ss]   End (Local) [yyyy/mm/dd|v] [hh:mm:ss] | |  <DatePicker><TimeInput>
| Analytics| +---------------------------------------------------------------------------+ | |
| >    | | | 1 | fields @timestamp, @message, @logStream, @log                         | | |  <CodeEditor>
|      | | | 2 | | sort @timestamp desc                                                 | | |
|      | | | 3 | | limit 20                                                             | | |
|      | | +---------------------------------------------------------------------------+ | |
|      | | [Run query]  Ctrl+Enter / Cmd+Enter                     [Examples v]          | |  <Button primary> <ButtonDropdown>
|      | +-------------------------------------------------------------------------------+ |
|      | +-- Results -------------------------------------------------------------------+ |
|      | |  No results yet                                                              | |  <Table empty>
|      | |  Choose log groups and a time range, write a query, then choose Run query.   | |
|      | +-------------------------------------------------------------------------------+ |
+------+-----------------------------------------------------------------------------------+
| Ready                                                                                    |
+------------------------------------------------------------------------------------------+
```

- 囲み「Log Analytics」の中に、上から ロググループ → 期間 → クエリ欄 → 実行の行 を置く（FR1.2）。
- ロググループ（Q2、FR1.3）：`<Multiselect>`。候補は今の接続で一覧したロググループ（Log Management の左ペインと同じ一覧を使う）。名前の部分一致で探せる。選んだものは欄の下にトークンで並び、× で外せる。一覧の読み込み中・失敗は欄の中に出す（画面 6）。
- 期間（FR1.4）：Log Management と同じ部品と決まり（`yyyy/mm/dd` の日付欄＋`hh:mm:ss` の時刻欄、ラベルにタイムゾーン、焦点が外れたら時刻を補う）。2 つの画面で期間の値は別々に持つ（クエリの画面で変えても Log Management の期間は変わらない）。
- クエリ欄（Q3）：`<CodeEditor>`、言語は独自の「Logs Insights のクエリ」。行番号あり、等幅、高さは 5 行から始めて手で伸ばせる。初めて開いたときは、コンソールの既定のクエリに相当する例を入れておく（中身は Functional Design で AWS の資料に合わせて決める。要件 OQ2）。
- 実行の行（FR1.6、FR1.7）：主ボタン [Run query] と、キーの組み合わせの表示（macOS は Cmd+Enter、Windows は Ctrl+Enter）。右に [Examples] のドロップダウン（例のクエリ、FR9.3、Should）。
- 結果の囲み「Results」：まだ実行していないときは空の状態の文言（FR7.2）。
- 2 つの画面を行き来しても、それぞれの画面の入力（選んだロググループ・期間・クエリの文・結果）は残す（A5 の「作り直すのは実行ボタンを押したときだけ」にならう）。

## 画面 4：実行中（足りない分の取得 → 評価）

```
| | Log groups  [/aws/lambda/app-a x] [/aws/lambda/app-b x]        (disabled)     |
| | Start (Local) [2024/03/01] [10:00:00]   End (Local) [2024/03/01] [12:00:00]   |  (disabled)
| | +---------------------------------------------------------------------------+ |
| | | 1 | fields @timestamp, @message | filter @message like /ERROR/            | |  (read-only)
| | +---------------------------------------------------------------------------+ |
| | [Run query] (disabled)   [Cancel]                                             |
| +-------------------------------------------------------------------------------+
| +-- Results -------------------------------------------------------------------+
| |  (o) Fetching missing logs: 2 log groups, 14 / 37 streams, 48,210 events       |  <StatusIndicator type=loading>
| +-------------------------------------------------------------------------------+
...
| (o) Running query                                                     00:00:12   |  status line + elapsed
```

- 実行ボタンを押すと、まずクエリの文を読み取る。書き間違い・対応外があれば取得せずに画面 7 のエラーにする（FR6.1、FR6.2）。
- 読み取れたら、足りない分の取得（FR2.2）→ 評価 の順に進む。どちらの段階かを結果の囲みの中の StatusIndicator で文字で示す（project.md の最低限の状態表示）。
  - 取得の段階：「Fetching missing logs」と、ロググループ数・ストリームの進み・件数。
  - 評価の段階：「Running query」と、評価した件数 / 全件。
  - 取得が要らないとき（FR2.3）は、取得の段階を出さずに評価の段階から始める。
- 実行中は、ロググループ・期間・クエリ欄・[Run query] を無効にする（クエリ欄は読み取り専用で、内容は見える）。[Cancel] で止められる（FR2.4、FR2.6）。
- ステータス行には今の取得と同じく経過時間を出す。
- 実行中に Log Management へ切り替えてもよい。2 つの画面は取得済みのログを共有しない（要件 FR2.1）ため、Log Management の表示中のログは変わらない。Log Management で同時に取得を始めてよいか（[Fetch] を押せなくするか）は Domain Design で決める（要件 OQ4）。クエリの画面に戻ると実行中の表示がそのまま見える。

- 列は `fields` で選んだ項目の順（FR7.1）。`fields` を書かないときの列はコンソールと同じ（要件 FR3.3、Functional Design で確かめる）。時刻の列はタイムゾーンを見出しに添えて、選んだタイムゾーンで出す。
- 囲みの見出しに件数（FR7.3）。`limit` や上限で打ち切ったときは「Showing N」と打ち切りの印を見出しの右に出し、ステータス行にも出す（FR3.7、FR7.3）。

- 結果の一覧は、件数が多くても見えている行だけを読む（FR7.5）。表の見た目は Log Management の表に合わせる。
- 一部のストリームの取得に失敗したとき（FR2.5）は、結果の囲みの上に警告を出す（画面 6c）。

## 画面 7：書き間違い・対応外のエラー（Q5、FR6）

```
| | +---------------------------------------------------------------------------+ |
| | | 1 | fields @timestamp, @message                                           | |
| | | 2 | | stats count(*) by bin(5m)                                           | |
| | |   |   ^^^^^                                       (red underline + gutter (x)) |
| | +---------------------------------------------------------------------------+ |
| |   (x) Line 2, column 3: "stats" is not supported in this version.            |  <FormField errorText>
| |       Supported commands: fields, filter, sort, limit.                       |
```

```
| |   (x) Line 1, column 8: The parenthesis is not closed.                        |
```

- 欄の直下に、行と列、どの言葉か、対応外か書き間違いか、を文字で出す（FR6.1、FR6.2）。対応外のときは、使える命令の一覧を添える。
- 欄の中では、該当する言葉に下線を引き、行番号の横に印を付ける（Q5）。印の上に重ねると同じ文が出る。色だけに頼らず、行番号の横の印（アイコン）と直下の文字で伝える。
- エラーのあともクエリの文は消さない（FR6.3）。欄を書き直すと、エラーの文と印は消える（次に [Run query] を押すまで出さない）。
- この段階では AWS を呼ばない（FR6.1）。

## 画面 8：書く手助け（FR9、Should）

```
| | | 2 | | filter le                                                             | |
| | |   |          +----------------------+                                     | |
| | |   |          | level        (field) |                                     | |  <CodeEditor> autocomplete popup
| | |   |          | like     (operator)  |                                     | |
| | |   |          +----------------------+                                     | |
```

- 補完（FR9.1）：命令の名前、決まった項目、演算子、クエリの画面で取得済みのログから見つけた JSON の項目の名前を候補に出す（2 つの画面は取得済みのログを共有しないため、最初の実行の前は JSON の項目の候補は出ない）。Ctrl+Space（macOS は同じ組み合わせ）で開き、↑↓ と Enter で選ぶ。
- 色分け（FR9.2）：命令・項目・文字列・数値・正規表現・演算子。色だけで意味を伝える場面はない（色分けは読みやすさのためで、エラーは画面 7 の文字と印で伝える）。
- 例のクエリ（FR9.3）：[Examples] から選ぶと、クエリ欄の中身を置き換える。欄に何か書いてあるときは、置き換えてよいか確認する（書いた文を黙って消さない）。
- 時間が足りないときは、この 3 つを次の版に回してよい（範囲 Q9）。回したときも画面 2〜7 は成り立つ（[Examples] を出さないだけ）。

## 最小ウィンドウでの配置

- 最小ウィンドウ 1024×640（今と同じ）。左端のナビゲーション（約 10rem、畳める）＋右の内容。クエリの画面は 1 列で、期間の 2 組が 1 行に収まらなければ終了を次の行に折り返す。
- 結果の表は横に長い値を省略記号で切り、行を開くと全文が出る。列の幅は手で変えられる。
