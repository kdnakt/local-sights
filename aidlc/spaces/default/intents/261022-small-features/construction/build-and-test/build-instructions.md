上流：U1・U2 の `code-generation-plan.md`（Testing Contract `sha256:1e653206…`）・`unit-test-instructions.md`・`code-summary.md`、`.github/workflows/ci.yml`、team.md の Code Style と Testing Posture。

## 1. 必要なもの

| もの | 版 | 用途 |
|---|---|---|
| Rust（stable、edition 2024） | `rust-toolchain` の指定どおり | 中核ライブラリ・Tauri アプリ |
| Node.js と npm | CI と同じ LTS（22） | 画面（React・Vite・Vitest） |
| cargo-llvm-cov | 0.9.1（CI と同じ） | ライブラリの行カバレッジ |
| cargo-deny | CI の cargo-deny-action と同じ系 | 依存関係のチェック（この作業で Rust の依存が 2 つ増えた） |
| Linux だけ：WebKitGTK・GTK の開発用パッケージ | CI の `tauri-app` ジョブと同じ | Tauri アプリのビルド |

AWS の認証情報は、ビルドにも自動テストにも要らない（project.md Forbidden）。この作業は AWS を新しく呼ばない。

## 2. 依存関係を入れる

```bash
npm ci
cargo fetch
```

この作業で足した依存関係は Rust の 2 つの公式プラグイン `tauri-plugin-dialog`（2.8.3）と `tauri-plugin-clipboard-manager`（2.5.0）だけ（U2、ADR-002）。どちらも MIT OR Apache-2.0。画面の依存関係は増えていない（`package.json` は変えていない）。`Cargo.lock` の差分は 2 つのプラグインとその推移的な依存（`tauri-plugin-fs` 2.7.1 を含む）と、付随する `tauri-utils` 2.10.1 → 2.10.2。

## 3. ビルド

```bash
# 画面（Tauri アプリの frontendDist）
npm run build          # = tsc --noEmit + vite build

# 中核ライブラリと Tauri アプリ
cargo build -p local-sights
```

tauri-build が `src-tauri/permissions/autogenerated/start_export.toml`・`dismiss_export_notice.toml` を生成する（既存の自動生成ファイルと同じく追跡する）。`src-tauri/gen/schemas/` も更新されるが、これは gitignore の対象。

## 4. ビルドの確かめ

CI と同じ順に流す。どれか 1 つでも失敗したらマージしない（team.md）。

```bash
npm run check:version              # 版のそろい（Cargo.toml・Cargo.lock・package.json・tauri.conf.json）
cargo fmt --all --check
cargo clippy --workspace --all-targets   # 警告はエラーにしない
npx tsc --noEmit
npx eslint .
npx prettier --check .
npx vite build
npm audit --audit-level=high
cargo deny check
```

## 5. よくあるつまずき

- **ディスクがいっぱいになる**：`target/` は clippy・テスト・カバレッジで別々のビルドを持ち 20 GB を超えることがある。`rm -rf target` して作り直す（Build and Test のコンテナで起きた）。
- **`npm audit --audit-level=high` が赤**：この作業の変更ではなく、既存の推移的な依存（`undici`、`zod`）の勧告。扱いは `test-results.md` の 1 と `security-test-instructions.md` の 4 を見る。
- **Linux で Tauri アプリがビルドできない**：WebKitGTK・GTK の開発用パッケージがない。CI の `tauri-app` ジョブの手順で入れる。
- **Vitest が負荷で timeout する**：`App.test.tsx` などの重い画面のテストは、同時に cargo のビルドを走らせていると 5 秒の timeout を超えることがある。単独で流し直す（`test-results.md` の 2）。
- **`cargo deny check` がない**：`cargo install cargo-deny --locked` で入れる。
