# 意図の確認（Intent Statement）

作業：261022-small-features（アプリ内の言語切替・書き出し・JSON の整形）

## 課題（Problem Statement）

- 社内の人がこのアプリで CloudWatch Logs のログを見る作業を、もっと楽にしたい。これがこの作業のいちばんの目的で、言語切替は「ついで」の位置づけ [Q1] [Q12]。
- 画面の言語（日本語・英語）は OS の言語でしか決まらないため、英語の画面を確かめるたびに `-AppleLanguages` で起動し直す手間がかかっている。画面の言語の仕組みそのものはすでにある [desc] [Q7]。
- ログやクエリの結果をアプリの外へ持ち出す手段がなく（IB-09）、JSON 形式のメッセージも API から返ったままの 1 行で出るため読みづらい（IB-10） [desc] [Q5]。

## 対象の利用者（Target Customer）

- 利用者は、開発者本人を含む社内の人。アプリは会社の PC に配っており、配布先の人も使う。ただし何を作るかを決めるのは開発者本人で、ほかの人の声は聞かない [Q8] [Q12]。
- 言語切替は利用者向けの機能として作り、誰でも切り替えられるようにする [Q2]。
- 書き出しは、ログの画面の「表示中のログ（絞り込みをかけた後）」と、クエリの画面の「実行結果」を対象にする [Q3]。
- 書き出しの形式と出し方はマネジメントコンソールに合わせる：CSV と Markdown が選べ、ファイルへの保存とクリップボードへのコピーの両方を用意する [Q4] [Q11]。
- JSON の整形は、行を開いたときの全文の表示だけに適用し、一覧の 1 行はそのままにする [Q5]。

## 成功の物差し（Success Metrics）

- 言語切替：アプリを起動し直さずに、画面の言葉が日本語と英語で入れ替わる [Q6]。
- 書き出し：保存したファイル（またはコピーした中身）を、使い道のツール（例：Excel、Markdown を貼れる場所）で開いて中身が読める [Q6] [Q11]。
- JSON の整形：JSON のメッセージが字下げと改行つきで読める。JSON でないメッセージは今までどおり出る [Q6]。
- 既存の機能と自動テストが、macOS と Windows の両方で今までどおりすべて通る [Q6]。

## きっかけ（Initiative Trigger）

- 前の作業（持ち越し Minor の一括修正）の手元の確認で、英語の画面を確かめるための言語の切替が面倒だったという、開発者自身の気づき [Q7] [desc]。
- 書き出し（IB-09）と JSON の整形（IB-10）は、依頼文で言語切替と合わせて 1 つの作業にすると決めたもの [desc]。
- この作業だけでは配らず、次の版に合わせて配る。配るときはチームの手順（版を上げる PR → Release dry run → 両 OS での手元の確認 → タグ）に従う [memory:M1]。

## 最初の範囲の手がかり（Initial Scope Signal）

### 進め方（workflow-selected）

- この作業の進め方は `refactor` を元にした独自の計画（small-features）。これは作業の進め方の選択であり、製品の範囲ではない [scope]。

### 製品として含めるもの（利用者が確認）

- アプリの中での日本語・英語の切替（利用者向け） [desc] [Q2]。
- ログの画面の表示中のログと、クエリの画面の実行結果の書き出し。CSV と Markdown、ファイルへの保存とクリップボードへのコピー [desc] [Q3] [Q4] [Q11]。
- 行を開いたときの全文の表示での JSON の整形 [desc] [Q5]。

### 製品として含めないもの（利用者が確認）

- stats による集計と、クエリ実行中の途中結果の表示（次の別の作業に回す） [desc]。
- 日本語・英語以外の言語を足すこと [Q10]。
- CSV・Markdown 以外の形式（JSON・Excel など）での書き出し [Q10]。
- JSON 以外の形式（XML など）の整形や、JSON の中の値の折りたたみ・検索 [Q10]。
- 書き出したファイルの再読み込み（アプリで開き直す） [Q10]。

### 守ること

- 画面は標準部品のみで作り込まない [memory:M2]。
- 書き出すファイルやコピーする中身にも、秘密の認証情報（シークレットアクセスキー・セッショントークン・SSO のトークン）とアクセスキー ID を書き込まない。ログの中身は利用者が取得したものをそのまま出す [memory:M3]。

## 進み具合の共有（Communication）

- 進み具合の共有や報告は要らない。開発者本人の作業で、報告先がない [Q9]。

## Assumptions & Open Questions

- [assumption] 「元のマネコンに合わせて」[Q4] の「マネコン」は、CloudWatch Logs のマネジメントコンソール（Logs Insights の「結果をエクスポート」）を指すと読んだ。保存とコピーのそれぞれでどの形式を用意するか（コンソールは保存が CSV、コピーが CSV と Markdown）は要件分析で決める。
- [assumption] ログの画面の書き出しの対象「表示中のログ」[Q3] は、絞り込みをかけた後に一覧に出ている行を指すと読んだ。取得したが絞り込みで隠れている行は含めない。
