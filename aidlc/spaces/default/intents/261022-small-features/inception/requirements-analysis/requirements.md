# 要件：アプリ内の言語切替・書き出し・JSON の整形（261022-small-features）

## 意図の分析

社内の利用者（開発者本人を含む）がこのアプリでログを見る作業を楽にするために、小さな機能を 3 つ足す（`ideation/intent-capture/intent-statement.md`）。

1. **アプリの中での言語切替**：画面の言葉を日本語と英語で切り替えられるようにし、英語の画面を確かめるたびに `-AppleLanguages` で起動し直す手間をなくす。対訳表と `translate` の仕組み（`src/i18n/messages.ts`）はすでにある（codekb の business-overview 12、code-structure「画面」）。
2. **書き出し（IB-09）**：ログの画面の表示中のログと、クエリの画面の実行結果を、CSV と Markdown で、ファイルへの保存とクリップボードへのコピーの両方で持ち出せるようにする。形式と出し方はマネジメントコンソールの「結果をエクスポート」に合わせる。
3. **JSON の整形（IB-10）**：行を開いたときの全文の表示で、メッセージの中の JSON を字下げと改行つきで読めるようにする。今は API から返ったままの文字列を出している（`src/components/ExpandedMessage.tsx`）。

種類：既存のデスクトップアプリへの機能追加（3 つは互いに独立）。範囲：画面（`src/`）、アプリ（`src-tauri/`：ファイル保存・クリップボード・設定の読み書きの境界）、中核ライブラリ（`crates/local-sights-core`：設定ファイル、純粋なロジック）。複雑さ：標準。配布の仕組み・AWS の呼び出し・CI は変えない（codekb の architecture「System Overview」）。

決めるのは開発者本人で、ほかの利用者の声は聞かない（intent-statement「対象の利用者」）。この作業だけでは配らず、次の版に合わせて配る（team.md Deployment）。

## Functional Requirements

### FR1 アプリの中での言語切替

対象：画面の言葉（`messages.ts` の対訳表）、Cloudscape の部品が持つ文言（`main.tsx` の `I18nProvider`）、リージョン名（`regions.ts`）、`document.documentElement.lang`。

- **FR1.1** 設定ダイアログに「言語」の選択を置く。選択肢は「OS の設定に合わせる」「日本語」「English」の 3 つ（RA Q1 A、Q2 A）。
- **FR1.2** 設定ダイアログの［保存］で言語を変えると、アプリを起動し直さずに、表示中の画面の言葉がすべて新しい言語に入れ替わる（intent-statement の物差し）。Cloudscape の部品の文言、リージョンの選択欄の名前、ページの `lang` 属性も合わせて変わる。
- **FR1.3** 選んだ言語は設定ファイル（今の `settings.json`）に保存し、次に起動したときも使う（Q2 A）。「OS の設定に合わせる」を選んでいるときは、今と同じく起動時に OS（ブラウザ）の言語から決める。
- **FR1.4** 設定ファイルに言語の項目がないとき（前の版からの更新を含む）や、知らない値のときは「OS の設定に合わせる」として扱う。既存のキャッシュの設定（`cacheEnabled`）はそのまま読める。
- **FR1.5** 言語を変えても、取得済みのログ・クエリの結果・開いた行・入力欄の文字・選んだ接続は失わない。
- **FR1.6** 設定の保存に失敗したときは、今のキャッシュの設定と同じ知らせ（`settings.notice.SaveFailed`）を出し、画面の言語は変えない。

受け入れ基準

- Given OS が日本語で、言語の設定が「OS の設定に合わせる」、When 設定ダイアログで「English」を選んで保存する、Then 画面の見出し・ボタン・表の列名・Cloudscape の部品の文言が英語になり、取得済みのログは表示されたままで、`settings.json` に英語の選択が書かれている。
- Given 上の状態、When アプリを終了して起動し直す、Then 画面は英語で始まる。
- Given 言語の項目のない `settings.json`（前の版のもの）、When 起動する、Then OS の言語で表示され、キャッシュの設定は保存どおりに読まれる。
- Given 設定ファイルに書けない（権限がない）、When 言語を変えて保存する、Then 保存に失敗した知らせが出て、画面の言語は変わらない。

### FR2 ログの画面の書き出し

対象：ログの画面（Log Management）の一覧。

- **FR2.1** 表示中のログ（絞り込みをかけているときは、絞り込みの結果として一覧に出ている行）を書き出せる。取得したが絞り込みで隠れている行は含めない（intent-statement の前提）。
- **FR2.2** 列は一覧と同じ 3 列（時刻・ストリーム・メッセージ）で、この順。時刻の文字は一覧に表示している文字（選んだゾーンで中核が作った文字）と同じにする（RA Q4 A）。
- **FR2.3** 行の順は一覧と同じ（時刻順）。メッセージは全文を入れる（一覧で省略されていても）。
- **FR2.4** 行の数に上限は置かない。100 万行でも全部を書く（Q3 A）。
- **FR2.5** 表示中の行が 0 のとき（取得前、絞り込みで 0 件）は、書き出しの操作を無効にする。
- **FR2.6** 取得中と絞り込みの走査中は、書き出しの操作を無効にする（一覧が変わる途中の内容を書かないため）。

受け入れ基準

- Given 1,000 行を取得し、絞り込みで 120 行が表示されている、When CSV で保存する、Then ファイルには見出し 1 行と 120 行があり、時刻の文字は一覧と同じで、行の順も一覧と同じ。
- Given 取得が終わって絞り込みなし、When Markdown をコピーする、Then クリップボードに全行の表が入る。
- Given 取得前、When 一覧を見る、Then 書き出しの操作は無効。

### FR3 クエリの画面の書き出し

対象：クエリの画面（Log Analytics）の結果の表。

- **FR3.1** 実行が終わって表に出ている結果の行を書き出せる。
- **FR3.2** 列は表と同じ（クエリの `fields` で決まる列。指定がなければ `@timestamp` と `@message`）で、この順。`@timestamp` の文字は表と同じ（選んだゾーン）。
- **FR3.3** `@message` は表のように 1 行目だけではなく、全文を入れる（Q5 A）。行を開いたときに見える項目のうち表に出ていないものは入れない。
- **FR3.4** 行の順と数は表と同じ（`sort` と `limit` の結果のまま。上限は置かない、Q3 A）。
- **FR3.5** 結果が 0 行のとき、実行中、結果がないときは、書き出しの操作を無効にする。

受け入れ基準

- Given `fields @timestamp, @message, level | limit 50` の結果が 50 行、When CSV で保存する、Then 見出しは `@timestamp,@message,level` の順で、50 行あり、`@message` には改行を含む全文が入っている。
- Given 実行中、When 表を見る、Then 書き出しの操作は無効。

### FR4 書き出しの共通の決まり（形式・出し方・ファイル・コピー）

FR2 と FR3 の両方に当てはまる。

#### FR4.1 形式と出し方

- **FR4.1.1** 形式は CSV と Markdown の 2 つ（intent-statement）。
- **FR4.1.2** 出し方はファイルへの保存とクリップボードへのコピーの 2 つで、CSV・Markdown のどちらも、保存とコピーのどちらでも選べる（intent-statement Q11 B、Q4 X）。
- **FR4.1.3** 書き出しの操作は、ログの画面とクエリの画面のそれぞれの一覧の近くに置く。置き方は標準部品のみで作る（project.md の決まり）。
- **FR4.1.4** 書き出した値（時刻の文字、ストリーム名、メッセージ、クエリの結果の値）は、画面が持っている文字をそのまま入れ、形式のための括りと逃がし以外の加工はしない。

#### FR4.2 CSV の形

- **FR4.2.1** 1 行目は列名の見出し。区切りはコンマ、行の終わりは CRLF（RFC 4180）。
- **FR4.2.2** コンマ・二重引用符・改行を含む値は二重引用符で括り、中の二重引用符は 2 つ重ねる。メッセージの中の改行はそのまま残す（値の中で改行する）。
- **FR4.2.3** 文字コードは UTF-8 で、先頭に BOM を付ける（Q6 A）。クリップボードへのコピーの CSV には BOM を付けない（貼り付け先で見えない文字になるため）。
- **FR4.2.4** 保存するファイルの拡張子は `.csv`。

#### FR4.3 Markdown の形

- **FR4.3.1** 見出し行・区切り行・値の行からなる表（GitHub 流の Markdown の表）。
- **FR4.3.2** 値の中の `|` は `\|` に逃がす。値の中の改行は表を壊さない形に置き換える（置き換え方は機能設計で決める）。
- **FR4.3.3** 保存するファイルの拡張子は `.md`。文字コードは UTF-8（BOM なし）。

#### FR4.4 ファイルへの保存

- **FR4.4.1** OS の保存ダイアログで保存先と名前を決める。既定の名前にはロググループ名（クエリの画面では最初のロググループ名）と書き出した日時を含める（具体の形は機能設計で決める）。
- **FR4.4.2** ダイアログを取り消したときは何も書かず、知らせも出さない。
- **FR4.4.3** 書けなかったとき（権限がない、ディスクがいっぱい、など）は、原因が分かる知らせを画面に出し、書きかけのファイルを残さない。
- **FR4.4.4** 保存が終わったら、保存先のパスを含む知らせを出す。

#### FR4.5 クリップボードへのコピー

- **FR4.5.1** コピーが終わったら、コピーした行数を含む知らせを出す。
- **FR4.5.2** コピーに失敗したときは、その旨の知らせを出す。

#### FR4.6 進み具合と二重の操作

- **FR4.6.1** 書き出しの処理中は、書き出しの操作を無効にし、処理中であることを示す（project.md の「最低限の状態表示」の決まり）。
- **FR4.6.2** 処理中にもう一度操作しても、二重には実行しない。
- **FR4.6.3** 処理中も、画面のほかの操作（スクロール、画面の切り替え）は応じる。

受け入れ基準

- Given メッセージに `a,b`・`"q"`・改行を含む 1 行、When CSV で保存する、Then その値は `"a,b"`・`"""q"""`・改行を含んだ 1 つの括りで書かれ、スプレッドシートで開くと 1 つのセルに元の文字が入る。
- Given メッセージに `x|y` を含む 1 行、When Markdown をコピーする、Then 表のセルは `x\|y` で、表の列数は崩れない。
- Given 保存ダイアログ、When 取り消す、Then ファイルは作られず知らせも出ない。
- Given 書けないフォルダ、When 保存する、Then 失敗の知らせが出て、途中のファイルは残らない。
- Given 100 万行の表示、When CSV で保存する、Then 処理中の表示が出て操作は無効になり、終わると全行が書かれていて、途中も画面は固まらない。

### FR5 JSON の整形

対象：ログの画面で行を開いたときの全文の表示（`ExpandedMessage`）。一覧の 1 行とクエリの画面は対象外（intent-statement Q5 A）。

- **FR5.1** メッセージの中に JSON のオブジェクトか配列が含まれているとき、その部分を字下げと改行つきで整形して表示する。メッセージ全体が JSON のときも、前に時刻や ID などの文字が付いて途中から JSON が始まるときも整形する（Q7 B）。前の部分はそのまま残し、JSON の部分だけを整形する。
- **FR5.2** JSON とみなす条件（どこから JSON が始まるとみなすか、末尾に文字が続くときの扱い、複数の JSON が並ぶとき）は機能設計で決め、純粋な関数として実装する。
- **FR5.3** JSON として読めない部分（壊れた JSON、`{` で始まるが閉じない、など）はそのまま表示し、誤って整形しない。
- **FR5.4** 整形は見た目だけで、元のメッセージは変えない。キーの順は元のまま、値の文字（数値の表記、文字列の中身）も変えない。
- **FR5.5** 開いた表示に「整形／元のまま」の切替を置く。初期値は「整形」。切替は行ごとに持ち、行を閉じて開き直すと初期値に戻る（Q8 B）。
- **FR5.6** JSON を含まないメッセージでは、切替を出さず、今までどおりの表示にする。
- **FR5.7** 整形した表示でも、今の全文の表示の振る舞い（文字の選択とコピー、20 行までの高さと内側のスクロール、Tab/Escape のキー操作、読み上げの名前）は変えない。
- **FR5.8** 整形した表示で文字を選んでコピーすると、整形後の文字がコピーされる。元の文字が要るときは「元のまま」に切り替えてコピーする。

受け入れ基準

- Given メッセージ `{"a":1,"b":[1,2]}`、When 行を開く、Then 字下げと改行つきの JSON が表示され、切替が「整形」になっている。
- Given メッセージ `2026-10-24T01:51:32Z abc-123 INFO {"a":1}`、When 行を開く、Then `2026-10-24T01:51:32Z abc-123 INFO ` はそのままで、続く JSON だけが整形されている。
- Given メッセージ `{"a":1,`（閉じていない）、When 行を開く、Then 元の文字がそのまま出て、切替は出ない。
- Given 整形された表示、When 「元のまま」に切り替える、Then API から返った文字列がそのまま出る。When 行を閉じて開き直す、Then 「整形」に戻る。
- Given JSON を含まないメッセージ、When 行を開く、Then 今までと同じ表示で切替はない。

## Non-Functional Requirements

- **NFR1 既存の機能とテストの維持**：既存の自動テスト（`cargo test`、Vitest）が macOS・Windows・Linux の各ランナーで今までどおりすべて通り、取得・表示・絞り込み・キャッシュ・SSO ログイン・中断・経過時間・クエリの振る舞いは変わらない（intent-statement の物差し）。
- **NFR2 応答性**：書き出しと JSON の整形で画面が固まらない。書き出しの処理中も画面はスクロールと画面の切り替えに応じる（FR4.6.3）。大きな行数での処理時間の目標値は決めない（利用者の答えに従い、上限を置かず時間がかかることを受け入れる、Q3 A）。
- **NFR3 両 OS で同じ振る舞い**：言語切替・保存・コピー・JSON の整形は macOS（Apple Silicon）と Windows 11（x64）で同じように動く。OS に触れる処理（保存ダイアログ、ファイルの書き込み、クリップボード）は境界のコードに閉じ込め、判断は OS に依存しない関数に寄せる（team.md Code Style）。
- **NFR4 テスト**：純粋なロジック（CSV と Markdown の組み立て、JSON の検出と整形、言語の決め方）はテストを先に書く。ファイル保存・クリップボード・設定の読み書きの境界は実装してからテストを書く（team.md Testing Posture）。行カバレッジ 80% の下限は下げない。
- **NFR5 秘密の扱い**：アプリ自身は、秘密の認証情報とアクセスキー ID を、設定ファイル・ログ・画面のエラー表示に書き込まない（project.md Forbidden）。書き出しの中身は利用者が取得したログそのものであり、アプリはその中身を検査も加工もしない（FR4.1.4）。
- **NFR6 アクセシビリティ**：足したボタン・選択・切替はキーボードで操作でき、読み上げの名前を持つ（今の部品と同じ水準）。

## Constraints

- 読み取り 3 操作以外の AWS の API は呼ばない。書き出しは取得済みの手元のデータだけを使う（project.md Forbidden）。
- 画面は Cloudscape の標準部品のみで作り込まない（project.md Corrections）。
- 設定ファイルは今の `settings.json`（`formatVersion: 1`、`cacheEnabled`）を広げて使う。別のファイルは作らない。
- 配布の仕組み（タグ → GitHub Releases）と CI の構成は変えない。この作業だけでは配らない。
- 言語は日本語と英語の 2 つ（intent-statement「含めないもの」）。

## Assumptions

- **AS1** 「表示中のログ」は、絞り込みをかけた後に一覧に出ている行を指す（intent-statement の受け入れ済みの前提）。
- **AS2** コンソールの「結果をエクスポート」に合わせるのは、CSV と Markdown という形式と、保存とコピーという出し方まで。コンソールの CSV の細部（見出しの文字、時刻の形）までは追わず、このアプリの表示に合わせる（Q4 A、Q5 A）。
- **AS3** スプレッドシートで式として解釈される値（`=` や `+` で始まる文字）を書き換える加工はしない。社内の利用者が自分で取得したログを自分で開く用途であり、FR4.1.4 の「値はそのまま」を優先する。危ないと分かったら見直す。
- **AS4** クリップボードへのコピーは、画面側（WebView）かアプリ側のどちらで行うかを設計で決める。どちらでも FR4.5 を満たす。
- **AS5** 言語切替は Cloudscape の日英の文言の束（`main.tsx` の `cloudscapeMessages`）がすでに両言語分あることを前提にする。
- **AS6** 書き出しの中断の操作は置かない。行は手元のメモリにあり、処理は AWS を呼ばないため、処理中の表示と二重実行の防止（FR4.6）で足りるとみなす。

## Out of Scope

- `stats` による集計、クエリ実行中の途中結果の表示（依頼文で次の別の作業に回した）。
- 日本語・英語以外の言語。
- CSV・Markdown 以外の形式（JSON・Excel など）での書き出し。
- JSON 以外（XML など）の整形、JSON の中の値の折りたたみ・検索。
- 書き出したファイルの再読み込み。
- 一覧の 1 行の中での JSON の整形、クエリの画面の値の整形（Q5 A）。
- 書き出しの範囲の指定（選んだ行だけ、など）と、絞り込みで隠れた行の書き出し。
- 設定ダイアログ以外の場所（上部のバー、メニュー）からの言語切替。

## Open Questions

- **OQ1** JSON とみなす条件の細部（最初の `{` か `[` から末尾まで読めるときだけか、末尾に文字が続いてもよいか、1 つのメッセージに JSON が 2 つ以上あるとき）→ 機能設計（FR5.2）。
- **OQ2** Markdown の値の中の改行の置き換え方（`<br>` か、空白か）→ 機能設計（FR4.3.2）。
- **OQ3** 保存するファイルの既定の名前の形 → 機能設計（FR4.4.1）。
- **OQ4** 書き出しの操作の置き方（1 つのメニューから形式と出し方を選ぶか、ボタンを並べるか）→ ドメイン設計・機能設計（FR4.1.3）。
