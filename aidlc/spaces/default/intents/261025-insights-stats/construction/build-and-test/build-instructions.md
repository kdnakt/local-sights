# Build Instructions — 261025-insights-stats

## 依存関係を入れる

- Rust：安定版のツールチェーン（`rustfmt`・`clippy` を含む）。`Cargo.lock` をコミットしてあり、新しい依存は足していない。
- Node.js と npm：`npm ci`（`package-lock.json` の版のまま入れる）。
- 確認の道具：`cargo-llvm-cov`（カバレッジ）、`cargo-deny`（依存関係の検査）。
- Tauri 2 のビルドに要る OS の部品は、今の手順書（`docs/releasing.md`）のとおり。

## 環境の用意

- 自動テストとビルドに、AWS の認証情報や環境変数は要らない。自動テストと CI は実際の AWS に接続しない（project.md Forbidden）。
- 手元の確かめ（`fetch_check`・`compat_check`・`insights-export.sh`）だけは、開発者本人の AWS 認証情報で動かす。手順は `README.md` の確認用プログラムの節。

## ビルドのコマンド

```bash
cargo build --workspace --all-targets   # 中核・アプリ・examples
npm run build                           # tsc --noEmit と vite build
npm run tauri build                     # 配布物（手元か CI のリリースのワークフロー）
```

## ビルドの確かめ

```bash
cargo fmt --check
cargo clippy --workspace --all-targets
npx prettier --check .
npx eslint .
npx tsc --noEmit
cargo deny check
npm audit --audit-level=high
```

どれも 0 で終わること。clippy は警告をエラーにしない（team.md Code Style）。

## よくある問題

- `src-tauri/gen/schemas/*.json` と `src-tauri/permissions/autogenerated/*.toml` は、コマンドを足すとビルドで作り直される（U2 の `get_query_catalog`、U3 の `find_query_row`）。作り直されたものはコミットする。権限の一致のテスト（`src/commandRegistration.test.ts`）が、3 か所の一覧の食い違いを見つける。
- Windows で取り出したときに `cargo fmt --check` や `prettier --check` が食い違うときは、`.gitattributes` の LF の設定を確かめる。
