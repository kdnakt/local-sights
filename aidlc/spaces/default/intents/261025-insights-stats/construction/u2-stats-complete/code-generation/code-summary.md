## 実装の主な決め方

- **QueryCatalog**
  - 命令・集計の関数・ほかの関数・キーワード・決まった項目を、1 つの一覧に持つ。
  - 命令と予約語は大文字・小文字を区別せずに引く。関数は書いたとおりにだけ引く。
  - パーサの `OTHER_COMMANDS`・`KEYWORDS`・U1 の暫定の表と、補完の候補は、この一覧から作る（BR4.1・BR4.3）。
- **読み取り**
  - stats のあとの命令の項目は、結果の列の名前で引いて `FieldRef::Column(ColumnRef { index, name, is_timestamp })` に解く（BR1.4）。
  - 時刻の列は @timestamp と同じく、日時の文字と比べられる。このため `instant.rs` の `resolve_date_texts` を広げた。
  - pct の百分位は `Percentile { numerator, scale }` の整数で持つ（BR1.2）。
  - 新しい問題の鍵は PCT_OUT_OF_RANGE・UNKNOWN_RESULT_COLUMN・FIELDS_AFTER_STATS・SECOND_STATS の 4 つ。U1 の UNSUPPORTED_AFTER_STATS は消した。鍵の数は 57。
- **集計**
  - count_distinct は値の文字の集まりで正確に数える（BR2.1）。
  - pct の順位は u128 の整数で求める（`percentile_rank`、BR2.2）。
  - stddev は Welford の方法（BR2.3）。
  - earliest・latest は、時刻・ロググループ・ストリーム・ストリーム内の順番の鍵で比べる。add を呼ぶ順番には左右されない（BR2.5）。
- **評価**
  - `condition_holds` を trait `FieldSource` で汎用にし、集計の行のセルにも今の filter の比べ方を使う（BR3.1）。
  - stats のあとの命令は `Stage::Finishing` で進める。filter は 10,000 行ずつ、sort と limit は 1 段ずつ進め、その間ごとに止める信号を確かめる。
  - 打ち切りと件数の数え方は events と同じにした（BR3.2）。
- **画面**
  - `get_query_catalog` のコマンドを足した。一覧は固定の定数で、AppState の鍵を取らない。
  - 色分けは、一覧が届くまで Ace のプレーンテキストのモードで動く。届いたら `registerQueryMode` で 1 回だけ登録して切り替える（BR4.2）。
  - 「使える命令」と「使える関数」の文は、一覧から差し込む。

## 利用者に諮ったこと（Step 12）

最初の基準 `stats count(*) by bin(5m)` に対しては、重いクエリが 7.29 倍だった。count_distinct をハッシュで持つ手を試しても 5.41 倍だった。主な原因は `latency` を取り出すための JSON の読み取りで、U1 の `sum(latency)` だけでも 3.8 倍になる。このため作業を止めて利用者に諮った。

- Q1 A：基準を、同じ JSON の項目を読む U1 のクエリ `stats sum(latency) by @logStream` に変え、3 倍以内は保つ。
- Q2 A：count_distinct は BR2.1 のとおり正確に数える形に戻す（ハッシュの手はやめる）。

## 計画からずれたところ

1. **pct の小数の上限**：百分位の小数は 15 桁まで（`MAX_PERCENTILE_DECIMALS`）とし、超えると PCT_OUT_OF_RANGE にした。u128 の計算があふれないようにするためで、設計にない新しい制限。
2. **BR1.4 (c) の `!=`**：BR1.4 (c) には「今の filter の比べ方をそのまま使う」とあり、こちらに従った。
   - そのため、値のない列に `!=` を書くと、イベントの値のない項目と同じく成り立つ。
   - `=`・`<`・`>`・`like`・列どうしの比較は成り立たない。
   - 同じ BR1.4 (c) の括弧書き「Missing はどの比較にも合わない」とは食い違う。
3. **打ち切りの注記の場所**：計画では QueryResultTable に出す予定だった。実際には、今の events の注記がある LogAnalyticsPage の結果の見出しに、集計の行のときだけ「行」の文言で出している。QueryResultTable.tsx は変えていない。
4. **期待値を変えた既存のテスト**：
   - parser の 2 つのテストと鍵の一覧（U1 で「対応していない」とした書き方。BR5.1 が認める範囲）。
   - evaluator の「aggregates は 10,000 で打ち切らない」のテスト：BR3.2 が U1 の決まりを明示して改めたため、打ち切るテストに変えた。
   - insights_session の補完のテスト（U1 の暫定の候補から BR4.3 の形へ）。
   - `messages.test.ts` の鍵の一覧（54 → 57）と supportedList の差し込みの形。
   - `LogAnalyticsPage.test.tsx` の使える命令の文（`stats` を足し、一覧が届くのを待つ）。
5. **作りだけ変えたテスト**：QueryEditor のテストは、色分けの規則を一覧の見本から作る形にした。出てくる色の期待値は前と同じ。
6. **文言**：「使える関数」の文（`insights.error.functionList`）と区切りの記号（`insights.error.listSeparator`）の鍵を足した。あわせて、`query.unsupported.function` と `query.unsupported.aggregateFunction` の文から関数を並べた部分を外した。
