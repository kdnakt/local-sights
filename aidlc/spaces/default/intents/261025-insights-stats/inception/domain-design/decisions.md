# Decisions — `stats` による集計と途中結果の表示（261025-insights-stats）

設計判断の記録（ADR）。部品の一覧は `components.md`、質問票の回答は `domain-design-questions.md`（Q1〜Q7）。各判断は、要件（`inception/requirements-analysis/requirements.md`）とそのレビュー（`reviews/review-01.md`）を根拠に書く。すべての判断に共通する安全の決まり：呼べる AWS API は読み取りの 3 つだけで新しい API は呼ばない（C1、NFR5）、クエリの文も結果も外部に送らない（NFR12）、エラー・画面・ログに秘密の認証情報とアクセスキー ID を出さない、自動テストと CI は実際の AWS に接続しない（C2）。

## ADR-001 集計の結果は、1 つの `QueryResult` の中で「形」として区別する

- **Status**: Accepted（Q1 A）
- **Context**: 今の結果は 1 行 = 1 イベントの写し（`ResultRow { event, log_group_name }`）に固定され、画面の表・行の詳細・書き出し・確認用プログラムがその形を前提にしている（codekb の構造上の制約 B）。集計の行は元のイベントを持たず、列も `by` の鍵と集計値になる（FR1.5、FR3.1）。前回の結果と今回の結果の形が違うとき、見出し・詳細・書き出しの列がいつ切り替わるかが決まっていなかった（R-02、FR3.6）。
- **Decision**: `QueryResult` を 1 つのまま、形（イベントの行か集計の行か）、列の名前の一覧、行の列挙型（イベントの行＝保持の位置とロググループ名、集計の行＝セルの値の列）を持たせる。結果を受け取る場所（InsightsSession・ExportJob・CompatCheck・画面）はこの形で分岐し、形が切り替わる時点は「新しい形の結果を受け取った時点」の 1 つに決まる。集計値の表示の文字は StatsAggregator が 1 回だけ決め、表と書き出しと確認用プログラムは同じ文字を使う（A7）。
- **Consequences**:
  - 良い点：受け取る場所が 1 つのまま。形の切り替えの判断を画面に散らさない。書き出し（FR3.4）と互換の確かめ（FR7.1）は結果の形で分岐するだけで足りる。
  - 受け入れる点：`QueryResult`・Tauri の値・画面の型・`ExportSnapshotSource::LogAnalytics` をそろえて変える（C3）。イベントの行の今のテストは形の追加に合わせて直す。
  - 安全：結果の型の変更は AWS 呼び出しに触れない。集計の行にはイベントの全文を持たせないため、書き出しに出る情報は表に出ている文字だけになる。
- **Alternatives Rejected**:
  - 別の型 `StatsResult` と別の表の部品（Q1 B）：受け取る場所が 2 つになり、形の切り替えと書き出しの分岐が画面側に散る。
  - イベントの行もセルの列に統一（Q1 C）：今の行の詳細（@message の全文と JSON の整形）と 1 行 = 1 イベントのテストを作り直すことになり、変える範囲が広い。

## ADR-002 集計は新しい部品 `StatsAggregator` が受け持つ

- **Status**: Accepted（Q2 A）
- **Context**: 使える集計の関数はコンソールの `stats` の関数すべて（FR1.2、RA Q1 C）で、13 種類以上の累積・`bin()` の区切り・`by` の鍵によるグループ化がある。今の `QueryEvaluator` は filter・fields・sort・limit の流れを持ち、純粋なロジックはテストを先に書く決まり（team.md Testing Posture、NFR7）。
- **Decision**: 集計の中身（グループ化、関数ごとの累積、`bin()` の区切り、集計値の型と表示の文字、空のビンを出さない決まり）を `StatsAggregator` に切り出す。`QueryEvaluator` は filter で残ったイベントを塊ごとに渡し、できた集計の行に対して `stats` のあとの sort・limit を行う（FR1.4）。
- **Consequences**:
  - 良い点：関数ごとのテストを部品の中で閉じられる。コンソールの細部（FR1.6、R-04）の確かめと直しが評価の流れに影響しない。
  - 受け入れる点：部品が 1 つ増え、`QueryEvaluator` と `StatsAggregator` の間の受け渡しの形を機能設計で決める。
  - 安全：純粋な部品で、ファイルも AWS も触らない。
- **Alternatives Rejected**:
  - `QueryEvaluator` を広げる（Q2 B）：1 つの部品が大きくなり、関数ごとのテストが評価の流れと混ざる。

## ADR-003 途中結果は「途中の view」を作って全体を評価し直し、最終結果と同じ並びに保つ

- **Status**: Accepted（Q3 A、Q5 A）
- **Context**: 今は取得中のイベントを範囲ごとの保持にため、範囲が終わってから `QueryStore::settle_range` で確定し、取得がすべて終わってから 1 回だけ評価する（codekb の構造上の制約 C）。2 回数えない・落とさない決まり（FR4.8）はこの確定の仕組みで守られている。途中結果はどのクエリにも出す（FR4.1、RA Q5 A）。FR4.2 の「末尾に足す・既存の行は動かない」と「時刻順の並びは最終結果と同じ」は両立しない（R-01）。評価は最終結果と同じ評価器を届いた分に走らせる前提（A5）。
- **Decision**: 確定の仕組みは変えない。`QueryStore` に「確定済みの分と、取得中の範囲ごとの保持の写しを合わせた途中の view」を作る入口を足し、`QueryRunner` が一定の間隔ごとにそれを同じ評価器で全体評価し直して差し替える。最終結果は今までどおり確定済みの分だけから作る。`filter`・`fields` だけのクエリも同じ道を通し、途中も最終結果と同じ並び（前の FR3.5）に保つ。新しい行が途中に挿入され、既に出ている行が動くことを許す。FR4.2 の文言と受け入れ基準は機能設計で「最終結果と同じ並びに保ち、行が途中に入ることがある」に改める（R-01 の (a)）。
- **Consequences**:
  - 良い点：FR4.8 を守る仕組みに触らない。評価の道が 1 本で、`sort`・`limit`・`stats` を含むクエリと含まないクエリで作りが分かれない。
  - 受け入れる点：途中結果のたびに全体を評価し直すため、取得済みが多いと 1 回の評価が重くなる。評価は blocking スレッドで塊ごとに進め取得を待たせず、前の評価が終わらないうちは次を始めない（NFR1・NFR2）。増分評価は NFR1 を満たせないときだけ作る段階で考える（A5）。表示済みの行が動くため、画面はスクロール位置・開いた行・選択をできるだけ保つ（FR4.4）。
  - 安全：保持の写しはメモリの中だけで、ファイルにもログにも書かない。
- **Alternatives Rejected**:
  - 届いたページごとに段階的に確定（Q3 B）：確定と「取得済みの範囲」の記録を分ける作り直しが要り、FR4.8 の守り方が変わる。
  - 増分評価（Q3 C）：速いが評価器に 2 つの入口ができ、`filter`・`fields` だけのクエリと他のクエリで作りが分かれる。
  - 途中は到着順に末尾に足し最後に並べ直す（Q5 B）：表示済みの行を覚える仕組みが要り、最終結果になる瞬間に並びが変わる。

## ADR-004 途中結果は「版が進んだ」ことだけをイベントで知らせ、画面が取りに行く

- **Status**: Accepted（Q4 B）
- **Context**: ログ管理の画面は `FetchSink::on_batch` → `fetch-progress`（`timelineVersion` つき）→ `get_rows` の形で、大きな結果をイベントに載せない。クエリの画面の `TauriQuerySink` は進み具合を 250 ms ごとに押し出すが、途中結果の入口がない。途中結果の版は新しく番号を持ち、古い版は捨てる（A4、R-07）。
- **Decision**: 中核の `QuerySink` に途中結果の通知（runId・版・結果）を足す。`TauriQuerySink` はそれを受けて `InsightsSession` の結果を差し替え、「結果の版が進んだ」ことだけをイベントで画面に知らせる。画面は版が新しいときだけ、コマンドで結果の見出し（形・列・件数・印）と行を取り直す。押し出す間隔は今の 250 ms にならい（数値は OQ3）、最終結果と中断後の結果は間隔に関わらずすぐ知らせる。古い版・別の runId の答えは画面と `InsightsSession` の両方で捨てる。
- **Consequences**:
  - 良い点：ログ管理の画面と同じ形で、イベントに大きな結果を載せない。画面は見えている範囲の行だけを取りに行ける（仮想スクロールのまま）。
  - 受け入れる点：イベントの後に往復が 1 回増える。コマンドの答えに版を添え、版の食い違いを捨てる判断が画面側に要る。
  - 安全：イベントとコマンドの値に認証情報は含まれない（結果の見出しと行だけ）。
- **Alternatives Rejected**:
  - 結果をイベントに載せる（Q4 A）：結果が大きいとイベントが重く、見えていない行まで毎回送ることになる。

## ADR-005 命令・関数・キーワードの一覧は中核の `QueryCatalog` に 1 つ持つ

- **Status**: Accepted（Q6 A）
- **Context**: 一覧がパーサ（`OTHER_COMMANDS`・`KEYWORDS`・`function()`）、画面の色分け（`analytics.ts`）、エラー文言（`messages.ts`）、補完の候補（`InsightsSession`）、README の表の 4〜5 か所に別々にあり、`stats` を足すと全部を変える必要がある（FR6.2、codekb の懸念）。
- **Decision**: 中核に `QueryCatalog`（命令・集計の関数・その他の関数・キーワードを、種類と対応の有無つきで列挙する純粋なデータ）を置く。`QueryParser` と `InsightsSession` の補完はこれを参照し、`TauriApp` はコマンドで画面にそのまま渡し、色分けの規則と「使える命令」のエラー文言は画面側がそこから作る。README の表は、この一覧と一致することをテストで確かめる（FR6.1、NFR7）。
- **Consequences**:
  - 良い点：対応する言葉が増えるとき、変える場所が 1 つ（README はテストが食い違いを知らせる）。
  - 受け入れる点：画面は一覧が届くまで色分けなしで動く。コマンドが 1 つ増える。
  - 安全：一覧は固定の語だけで、利用者の入力も認証情報も含まない。
- **Alternatives Rejected**:
  - 複数の場所に持ち、一致をテストで確かめるだけ（Q6 B）：部品は増えないが、変えるときに 4〜5 か所を触り、テストが落ちてから直す流れになる。

## ADR-006 形の切り替えは最初の途中結果の時点、中断は止めた時点の分で評価した最終結果とする

- **Status**: Accepted（Q7 A、RA Q6 A）
- **Context**: 実行を始めても前回の結果を「前回の結果」の印つきで最初の途中結果が届くまで残す（FR4.7、A3）。前回と今回で結果の形が違うとき、2 つの形が表に混ざらないよう切り替える時点を 1 つ決める必要がある（R-02）。中断は、前の作業の決まり（前の FR2.6：評価しない）を改め、止めた時点までの結果を印つきで出す（FR5.1、RA Q6 A）。C5 は「前の作業のクエリの振る舞いは変えない」と書くが、FR5.1 はその例外になる（R-07）。
- **Decision**: 前回の結果は前回の形のまま印つきで残し、最初の途中結果（または途中結果を経ない最終結果、FR4.9）を受け取った時点で、見出し・行の詳細・件数表示・［Export］の列をまとめて今回の形に切り替える。結果の型が形を持つ（ADR-001）ため、画面は受け取った結果の形に従うだけでよい。［Cancel］では、`QueryRunner` が止めた時点の確定済みの分と保持の写しで 1 回評価し、「一部のログだけの結果（中断）」の印つきの最終結果として知らせる。途中まで取得した範囲は確定しない（FR5.3）。中断後の結果は書き出せるが、印はファイルに含めない（FR5.2。理由は機能設計で R-08 に答える）。この中断の扱いを C5 の明示的な例外とし、ログ管理の画面の中断は変えない。
- **Consequences**:
  - 良い点：形の切り替えの時点が 1 つで、2 つの形が混ざらない。中断してもそれまでの取得が無駄にならない。
  - 受け入れる点：中断後に 1 回の評価が入るため、止めてから結果が出るまでに少し間がある。中断の表示を「止めた」だけから印つきの結果に変える。前の作業の中断のテストは FR5.1 に合わせて直す。
  - 安全：中断後の評価もメモリの中だけで行い、AWS は呼ばない。
- **Alternatives Rejected**:
  - 形が違う実行のときだけ実行の開始で前回の結果を消す（Q7 B）：形の比較が画面に要り、同じ形のときと振る舞いが分かれる。
  - 実行の開始で常に前回の結果を消す（Q7 C）：FR4.7 の見直しになり、途中結果が届くまで表が空になる。
  - 中断で途中結果も消す（RA Q6 B）：利用者が選ばなかった。
