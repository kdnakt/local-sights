## 1. 意図の分析

- **何を達成したいか**：Log Analytics のクエリで、コンソールの Logs Insights と同じように `stats` で集計（件数・合計・平均・最小・最大など）し、`bin()` で時刻ごとに区切って眺められるようにする。あわせて、クエリの実行中に、取得が進むにつれて結果の表の行が増えていくようにし、長い取得の間も結果を見始められるようにする（[desc]）。
- **誰のためか**：前の作業と同じ。開発者本人、同じ会社の同僚、OSS の利用者。
- **できたと言える目安**：コンソールで書いていた `stats` のクエリが、このアプリが対応する範囲ではそのまま書けて、同じ集計の結果になる（SM1）。クエリを実行すると、取得が終わる前に結果の表に行が現れ、取得が進むにつれて増える（SM2）。
- **種類と規模**：既存のアプリ（Rust の中核ライブラリ・Tauri・React）への機能追加。中核のクエリの層（読み・計画・評価・実行・保持）と、クエリの画面（結果の表・進み具合）、書き出し、互換の確かめの 4 か所に手が入る。AWS の新しい API は呼ばない（[desc]）。
- **複雑さ**：Standard。今のコードは (1) `stats` を読みの時点で拒み、(2) 結果の行を「1 行 = 1 イベントの写し」に固定し、(3) 評価を取得完了後に 1 回だけ走らせているため（codekb）、この 3 点を変える設計判断が要る。コンソールの細部は AWS の資料で確かめる（前の作業の決まり）。

## 2. 機能要件

### FR1. `stats` 命令（[desc]、RA Q1・Q3）

- **FR1.1** クエリに `stats <集計>, ... [by <鍵>, ...]` の命令を書ける。書き方（`as` による列の名前、`by` の鍵の区切り、関数の引き数）はコンソールの Logs Insights と同じにする。
- **FR1.2** 使える集計の関数は、コンソールの Logs Insights の `stats` で使える集計の関数すべてとする（RA Q1 C）。少なくとも `count(*)`・`count(項目)`・`count_distinct`・`sum`・`avg`・`min`・`max`・`pct`（パーセンタイル）・`stddev`・`earliest`・`latest`・`sortsFirst`・`sortsLast` を含む。確定した一覧と各関数の引き数・結果の型は、Functional Design で AWS の資料から起こす（OQ1）。
- **FR1.3** `by` の鍵には、決まった項目（`@logStream`・`@log` など）、JSON の項目、`bin()` による時刻の区切り、`as` で名前を付けた式を使える。`by` を書かないときは、全体を 1 つの行に集計する。
- **FR1.4** `stats` の前には今までどおり `fields`・`filter` を書け、集計は `filter` で残ったイベントに対して行う。`stats` のあとには `sort`・`limit` を書け、集計の結果の列（`as` で付けた名前を含む）で並べ替えと件数の制限ができる（RA Q3 A）。`stats` のあとに `fields`・`filter` を書く、`stats` を 2 回書く、の扱いはコンソールと同じにする（OQ2）。
- **FR1.5** 集計の結果の行は、`by` の鍵の列と集計値の列からなり、元のイベントを持たない。集計値の型（整数・小数・文字列・時刻）と表示の形（小数の桁、`bin()` の時刻の文字）はコンソールと同じにし、時刻は画面で選んでいるタイムゾーンで表示する（前の FR7.1）。
- **FR1.6** `by` の鍵の項目を持たないイベント、集計する項目を持たないイベント、数値でない値を `sum`/`avg` した場合の扱いは、コンソールと同じにする（OQ2）。
- **FR1.7** `stats` を含むクエリの結果の件数の上限（`limit` を書かないとき）は、コンソールと同じにする（OQ2）。上限で打ち切ったときはそのことを示す（前の FR3.7）。
- **FR1.8** `stats` の読み・計画・評価は、今までどおり取得したログに対して手元で行い、AWS の Logs Insights の API（StartQuery など）は呼ばない（C1）。

受け入れ基準：
- Given `level` が `error` のイベントが 3 件、`info` が 5 件ある When `stats count(*) by level` を実行する Then 結果は 2 行で、`level` と `count(*)` の列を持ち、`error` の行は 3、`info` の行は 5 になる
- Given `latency` が 100・200・300 のイベントがある When `stats avg(latency) as a, max(latency) as m` を実行する Then 結果は 1 行で、`a` が 200、`m` が 300 になる
- Given `stats count(*) as n by level | sort n desc | limit 1` When 実行する Then 結果は件数が最も多い `level` の 1 行だけになる
- Given `filter @message like /ERROR/ | stats count(*)` When 実行する Then `ERROR` を含むイベントの件数だけが 1 行で出る
- Given 結果の行を開く When 集計の結果の行を開く Then 元のイベントの全文は出ず、その行の鍵と集計値だけが見える（FR3.3）

### FR2. `bin()` による時刻の区切り（[desc]、RA Q2）

- **FR2.1** `by bin(<間隔>)` で、イベントを `@timestamp` の時刻ごとに区切って集計できる。間隔の書き方（`5m`・`1h`・`30s` など）と区切りの揃え方（どの時刻を区切りの始まりにするか）はコンソールと同じにする（OQ2）。
- **FR2.2** イベントのない区切り（空のビン）の行は出さない。コンソールと同じにする（RA Q2 A）。
- **FR2.3** 区切りの時刻の列は、画面で選んでいるタイムゾーン（ローカルか UTC）で表示する。区切りの計算そのものはタイムゾーンに依存せず、コンソールと同じ基準で行う（OQ2）。

受け入れ基準：
- Given 10:00〜10:15 の 15 分間に、10:01 と 10:03 に 1 件ずつ、10:12 に 1 件のイベントがある When `stats count(*) by bin(5m)` を実行する Then 結果は 2 行（10:00 の区切りが 2、10:10 の区切りが 1）で、10:05 の区切りの行は出ない
- Given 画面のタイムゾーンを UTC からローカルに切り替えた When 同じクエリの結果を見る Then 区切りの時刻の文字はローカルの表記に変わり、行の数と集計値は変わらない

### FR3. 集計の結果の表示（前の FR7、RA Q4）

- **FR3.1** 結果の表には、`by` の鍵の列と集計値の列を、クエリに書いた順で出す。`as` で名前を付けた列はその名前で出す。
- **FR3.2** 結果が 0 行（`filter` で全部落ちた、取得したイベントがない）のときは、0 行であることを示し、失敗とは区別する（前の FR7.2、corner：空・読み込み中・エラーは別の表示）。
- **FR3.3** 集計の結果の行を開いたときは、その行の鍵と集計値を項目ごとに見せる。元のイベントの全文表示（`@message` の整形を含む）は、集計の結果にはあてはまらない。
- **FR3.4** 集計の結果の行も、CSV / Markdown の書き出しの対象にする。表に出ている列（鍵と集計値）を、表の文字と同じ形でそのまま書く。既定のファイル名・形式・出し方・通知は前の作業の書き出しと同じ（RA Q4 A）。
- **FR3.5** 結果の表の列の数が多いとき（鍵と集計を合わせて 10 を超えるなど）も、表は横にスクロールして読める。
- **FR3.6** クエリの画面の結果の表は、集計の結果と 1 行 = 1 イベントの結果の両方を、同じ場所に表示する。どちらの形かは利用者が意識せずに使える。

受け入れ基準：
- Given `stats count(*) by bin(5m)` の結果が表に出ている When ［Export］から「Save as CSV」を選ぶ Then CSV の見出しは表の列名（`bin(5m)` と `count(*)`）で、各行は表の文字と同じ値になる
- Given `filter` ですべてのイベントが落ちる `stats count(*) by level` When 実行する Then 結果は 0 行であることが示され、エラーの表示にはならない

### FR4. 途中結果の表示（[desc]、RA Q5）

- **FR4.1** クエリの実行中、取得が進むにつれて、そこまでに取得したイベントに対してクエリを評価した結果（途中結果）を結果の表に出す。どのクエリにも適用する（RA Q5 A）。
- **FR4.2** `filter`・`fields` だけのクエリでは、新しく届いたイベントから条件に合う行を表の末尾に足す（既に出ている行は動かない。時刻順の並びは最終結果と同じ決まり（前の FR3.5）に従う）。
- **FR4.3** `sort`・`limit`・`stats` を含むクエリでは、届いた分で結果を作り直し、表を差し替える。集計値が更新され、並び順が入れ替わることがあることを受け入れる（RA Q5 A）。
- **FR4.4** 途中結果の更新の間隔は、画面が操作に応じたままでいられる頻度にし（前の作業の進み具合の押し出しが 250 ms ごとであることにならう）、数値は設計で決める（OQ3）。更新のたびに利用者の操作（スクロール位置、開いた行、選択）をできるだけ保つ。
- **FR4.5** 途中結果が出ている間は、それが途中であること（取得が続いていること、いくつのロググループ・範囲のうちどこまで終わったか）を表のそばに示す（前の FR2.4、project.md Corrections の最低限の状態表示）。
- **FR4.6** 取得がすべて終わったあとの最終結果は、今までどおり全部の取得済みのログに対して評価した結果とし、途中結果の差し替えの延長として表に出す。最終結果になったことを示す（途中の印を消す）。
- **FR4.7** 実行を始めたとき、前回の結果は最初の途中結果が届くまで「前回の結果」の印つきで残し、届いたら差し替える（前の作業の「前回の結果」の決まりを引き継ぐ。A3）。
- **FR4.8** 途中結果の評価のために、取得の途中で取り込んだイベントが、最終結果で 2 回数えられたり落ちたりしないこと（前の FR2.7）。
- **FR4.9** 期間がすべて取得済みで AWS を呼ばないとき（前の FR2.3）は、途中結果を経ずに最終結果を出してよい。
- **FR4.10** 途中結果の表示中も、ログの画面への切り替え、スクロール、行の開閉はできる。途中結果の書き出し（［Export］）は、実行が終わるまで無効にする（前の FR3.5 の「実行中は無効」を引き継ぐ）。

受け入れ基準：
- Given 取得済みでない範囲を 3 つ含むクエリ `filter @message like /ERROR/` When 実行する Then 1 つ目の範囲の取得が進むうちに条件に合う行が表に現れ、2 つ目・3 つ目が進むにつれて行が末尾に増え、取得がすべて終わると最終結果になる
- Given 同じ条件で `stats count(*) by level` When 実行する Then 取得が進むにつれて `count(*)` の値が増えていき、取得がすべて終わると最終の値になる
- Given 途中結果が出ている When ［Export］を見る Then 無効になっていて、実行が終わると有効になる
- Given 途中結果が出ている When 行を開いてスクロールする Then 次の更新のあとも、開いた行とスクロール位置ができるだけ保たれる
- Given 期間がすべて取得済み When クエリを実行する Then AWS を呼ばず、最終結果がそのまま出る

### FR5. 中断と途中結果（RA Q6）

- **FR5.1** 取得の途中で［Cancel］を押したときは、止めた時点までに取得した分でクエリを評価した結果を、「一部のログだけの結果（中断）」の印つきで最終結果として出す（RA Q6 A。前の FR2.6 を改める）。
- **FR5.2** 中断後の結果は、書き出し（［Export］）の対象になる。印は結果の表のそばに出し、書き出しのファイルには含めない。
- **FR5.3** 止める前に取得できた範囲は、前の FR2.6 のとおり取得済みとして残してよい。途中まで取得した範囲は取得済みとみなさない（前の FR2.5 と同じ）。
- **FR5.4** 取得の一部のストリームが失敗したときの扱いは前の FR2.5 のまま（取得できた分で評価し、一部のログだけの結果であることと失敗したストリームを示す）。中断と失敗が両方あるときは、両方を示す。

受け入れ基準：
- Given 取得に時間がかかるクエリを実行中で、途中結果が表に出ている When ［Cancel］を押す Then 取得は止まり、止めた時点までの結果が「一部のログだけの結果（中断）」の印つきで最終結果として残り、［Export］が有効になる
- Given 取得が始まる前（ストリームの列挙中）に［Cancel］を押した When 止まる Then 結果は 0 行で、中断の印が出る

### FR6. 対応範囲の一覧・補完・色分け・文言（前の FR8・FR9、codekb）

- **FR6.1** README の対応する命令・関数の一覧に `stats` と集計の関数、`bin()` を足し、「Not supported」の表から外す（前の FR8.1）。
- **FR6.2** クエリの画面の「使える命令」のエラー文言、エディタの色分け（命令・関数）、補完の候補（命令・関数・`by`）を、対応する範囲とそろえる。命令と関数の一覧がコードの複数の場所に別々にあるため（codekb：パーサ・色分け・文言・README・補完の 4〜5 か所）、1 か所を変えれば残りがそろう作りにするか、そろっていることをテストで確かめる（NFR7）。
- **FR6.3** 対応外の関数や書き間違いのエラーは前の FR6 のまま。`stats` の書き間違い（`by` のあとに何もない、閉じていない括弧、引き数の数の違い）も取得の前にエラーにし、場所を示す。

### FR7. 互換の確かめ（前の NFR3、RA Q7）

- **FR7.1** 手元の確認用プログラム（`compat_check`）に、`stats` を含むクエリを比べる仕組みを足す。集計の行の集まり（鍵と集計値）が一致することを比べ、`sort` を書いたクエリだけ並び順も比べる（RA Q7 A）。
- **FR7.2** 互換を確かめるクエリの組に、`count(*) by bin(5m)`、`by` の鍵が JSON の項目のもの、`avg`/`sum`/`max`/`min`、`count_distinct`、`pct`、`stats` のあとの `sort`/`limit` を含む例を足す。具体的なクエリは AWS の資料の例と開発者のロググループに合わせて Functional Design で決める（OQ4）。
- **FR7.3** 空のビンを出さない（FR2.2）など、コンソールと同じにした決まりはこの組で確かめる。コンソールと食い違う拡張（前の FR5.6 の日時の文字列との比較など）は組に入れない（前の作業と同じ）。

## 4. 制約

| ID | 制約 | 出典 |
|----|------|------|
| C1 | 呼べる AWS API は読み取りの 3 つだけ。集計もすべて手元で評価する | project.md Forbidden、[desc] |
| C2 | 自動テストと CI からは実際の AWS に接続しない | project.md Forbidden |
| C3 | 中核ライブラリ（判断）と Tauri アプリ（配線）と画面（表示だけ）の分け方を保つ。結果の形を変えるときは中核・アプリ・画面・書き出し・確認用プログラムをそろえて変える | codekb architecture（ADR-001）、codekb の懸念 |
| C4 | この作業だけでは配らない。配布は次の版で、手順書どおりに行う | team.md Deployment |
| C5 | ログの画面（取得・絞り込み・キャッシュ・SSO・中断）と、前の作業で作ったクエリの振る舞い（`fields`・`filter`・`sort`・`limit`、足りない分だけの取得）は変えない。既存のテストはすべての OS で通った状態を保つ | team.md Testing Posture、前の C5 |

## 5. 前提（Assumptions）

| ID | 前提 | 理由 |
|----|------|------|
| A1 | 「など」（[desc]）はコンソールの `stats` の集計関数すべてを指す | 利用者の答え（RA Q1 C） |
| A2 | 集計の結果の行の型は中核に新しく作り、1 行 = 1 イベントの結果と同じ `QueryResult` の中で区別する。画面・書き出し・確認用プログラムはその区別に従う | codekb：集計の行を表す型がどこにもない。形の決め方は Domain Design |
| A3 | 実行を始めたとき、前回の結果は最初の途中結果が届くまで残す（FR4.7）。前回の結果と新しい途中結果を同時に出すことはしない | 前の作業の「前回の結果」の決まりと矛盾させないため。途中結果が届くまでの空白を避ける |
| A4 | 途中結果の「版」は新しく番号を持つ（ログの画面の `timelineVersion` にならう）。古い版の結果が後から届いても捨てる | corner：古い応答が後から届く。codekb：`holdings_epoch` は廃止済み |
| A5 | 途中結果の評価は、最終結果と同じ評価器を届いた分に対して走らせる（増分の最適化は性能の要件（NFR1）を満たせないときだけ設計で考える） | 単純さを優先。`sort`・`limit`・`stats` は作り直しが要るため（RA Q5 A） |
| A6 | 単一の利用者・手元の PC で動くアプリのため、権限・テナント・個人データの決まりは加えない | corner-checklist の使い方（配置の形を先に決める） |
| A7 | 集計値の表示の桁・丸めはコンソールと同じにし、表示用の丸めと書き出しの文字は同じ文字を使う（表と CSV で値が食い違わない） | corner：同じ事実は同じ値・同じ丸め |
| A8 | `bin()` の区切りの計算は UTC のエポックを基準にし、タイムゾーンは表示にだけ効く（FR2.3）。コンソールと食い違うと分かったら Functional Design で改める | コンソールの振る舞いの一般的な理解。OQ2 で確かめる |
