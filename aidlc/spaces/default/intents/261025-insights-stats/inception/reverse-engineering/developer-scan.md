  1. **`stats` はパーサで拒まれる**。`crates/local-sights-core/src/query/parser.rs:186-199` の `OTHER_COMMANDS`（`stats`、`parse`、`dedup`、`display`、`pattern`、`diff`、`unmask`、`unnest`、`lookup`、`filterindex`、`source`）に当たる命令名は `command()`（`parser.rs:841-872`）が `QueryProblem::unsupported(keys::UNSUPPORTED_COMMAND, word, span)` を返し（`parser.rs:862-866`）、読みの時点で止まる（何も取得しない）。`count(*)`・`sum()`・`bin()` などは `function()`（`parser.rs:1131-1157`）が `toMillis` 以外を `UNSUPPORTED_FUNCTION` で拒む（`fields count(*)` のテストが `word = "count"` を確かめる、`parser.rs:2318-2320`）。`by` は語句（`KEYWORDS` は `and`/`or`/`not`/`like`/`in` の 5 つ、`parser.rs:202`）に入っていない。画面はこの問題を `query.unsupported.command`（「「{word}」にはこの版では対応していません。」）と `insights.error.supportedList`（「使える命令：fields、filter、sort、limit」、`src/i18n/messages.ts:680-683`）で出し、エディタの色分け（`src/analytics.ts:116-143`）は `fields|filter|sort|limit` と `toMillis` しか知らない。`README.md:200-204` の「Not supported」の表にも `stats` がある。
  2. **結果の行は「1 行 = 1 イベントの写し」で固定されている**。`QueryPlan` の命令は `Filter` / `Fields` / `Sort` / `Limit` の 4 種（`plan.rs:367-377`）、`columns()` は `Vec<FieldRef>`（固定 5 項目か JSON の項目、`plan.rs:146-160`）。`Evaluation` は保持の位置の列 `rows: Vec<usize>` を命令ごとに絞り・並べ・切り（`evaluator.rs:333-369`）、終わりに `QueryStore::copy_rows` が `ResultRow { event: LogEvent, log_group_name }` を複製する（`store.rs:528-544`、`evaluator.rs:761-786`）。セルの文字は表示のたびに `row_cells(columns, EventFields, format_time)` が計算する（`evaluator.rs:858-872`、`insights_session.rs:1130-1163`）。`QueryRow` は `LogEvent` を `#[serde(flatten)]` で含み（`insights_session.rs:402-415`）、`ResultSummary.columns` は `Vec<String>`。書き出しも `ExportSnapshotSource::LogAnalytics { columns: Vec<FieldRef>, rows: Vec<ResultRow> }` から `row_cells` で文字にする（`exporter.rs:216-236`、`insights_session.rs:1245-1255`）。集計の行（グループの鍵と集計値だけで、元のイベントがない）を表す型は中核にも画面にもなく、`stats` を入れるには `QueryResult` / `QueryRow` / `ExportSnapshotSource` / `row_detail`（開いた行の項目）に「集計の行」の形を足すか、`ResultRow` を列挙型にする必要がある。
  3. **評価は取得がすべて終わってから 1 回だけ走り、途中結果は出ない**。`run_query`（`runner.rs:224-270`）は `begin_run` → `fetch_missing`（選んだロググループを順に、足りない範囲を順に `fetch_range` で取得）→ `on_fetch_ended` → `build_view` → `gather_field_names` → `evaluate_held` の順で、評価（`evaluate_held`、`runner.rs:543-592`）は固定された世代の一覧の上で 10,000 行ずつ進み、終わりに `copy_rows` → `on_evaluated(QueryResult)` を 1 回だけ呼ぶ。`QuerySink`（`runner.rs:152-177`）に部分的な結果を渡す口はなく、`on_evaluation_progress` は件数だけ。取得中のイベントは `fetch_range` が範囲ごとに作る `Arc<Mutex<EventTimeline>>` の holder に積まれ、範囲の取得が終わってから `settle_range` で `QueryStore` に渡る（`runner.rs:405-466`）ので、取得の途中では `QueryStore` にもまだ入っていない。`InsightsSession` の相は `Fetching → Evaluating → Done` で、`result` が入るのは `finish_evaluation`（`insights_session.rs:991-1004`）だけ。実行中は前回の結果を残して見せる（`U3:BR3.4`、`begin` が `result: self.run.result.take()` で持ち越す、`insights_session.rs:762-771`）。画面の `ResultBody`（`LogAnalyticsPage.tsx:628-668`）は `result !== null` のときだけ `QueryResultTable` を描き、実行中は `previous` の印を付ける。`get_query_rows(runId, offset, limit)` は結果の複製から読む（`QueryResultTable.tsx:113-132`）。「取得が進むにつれて表の行が増える」には、(a) 範囲の途中でも保持に積む（または holder から読む）、(b) 評価を増分で進める（`filter` は増分できるが `sort`/`limit`/`stats` は再計算になる）、(c) `QuerySink` に途中結果の口を足し、`InsightsSession` に「途中の結果」の状態と版を持たせ、画面が実行中も表を読む、の 3 か所の変更が要る。`TauriQuerySink::update_progress` の 250 ms（`lib.rs:251`、`1966-1982`）が進み具合の押し出しの間隔。
